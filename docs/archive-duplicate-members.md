## 采用的行为

- 仅允许名称逐字一致的重复普通文件。先保留第一个成员，后续每份都完整读取并验证长度、内容摘要和相关文件属性，再丢弃重复正文。
- ZIP/JAR/WAR/EAR/AAR 及 TAR、gzip/bzip2 TAR 使用相同逻辑；旧 GNU sparse 兼容路径核对展开后的逻辑正文。
- ZIP 用对应的 `ZipInfo` 读取每一份，不按名称查询而误读最后一个条目。每份 CRC、加密/损坏检查照常进行。
- 不为正常单一成员新增摘要或全包扫描；重名成员在既有消费循环里分块计算 SHA-256，不额外读一遍正文，不写第二份临时文件。
- 成员数、声明展开量、实际读取量按所有副本计。即使成员被排除，也要校验每份内容；排除正文仍不落盘。固定排除计划的磁盘估算对同一路径只保留一份正文。
- 大小写不同、不同写法归一化后相同、真实 Windows 短别名、文件/目录冲突和链接仍拒绝。内容或相关属性不同也拒绝，不能选第一份或最后一份当作正确结果。
- ZIP 相关属性为来源系统和外部/内部文件属性；TAR 为权限、uid/gid、属主/组名。容器压缩方式、记录时间可不同，这些不改变展开文件的正文。
- 普通压缩包报告通过比较说明标注重复项数量；递归报告按旧/新侧列出原始成员名及份数，并做 HTML 转义。交付包原样保留，主清单、统计和上线说明不因递归去重而改变。

原有“不同正文的同名文件必须在写任何成员前失败”测试改为验证拒绝冲突且绝不覆盖第一份正文；因为正文是否相同只能在读取之后确认。构造失败仍清理本次完整临时树，没有发布部分结果。
