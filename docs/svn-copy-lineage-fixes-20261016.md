# 2026-10-16 SVN 多版本复制与替换修复

基于 `f2ef58f346feb543875c2753e31ed5701d2267f8` 修复再次审查发现的三个问题。本记录保存本地 Windows 源码验收结果；后续已重新打包为 `2026.10.16.2`，真实窗口及业务冒烟见 [发布记录](release-20261016-svn-lineage.md)。

## 修复内容

1. **已消失的旧路径被重新导出**：同 revision 中目录复制到两个目标，其中一个副本的子文件又被删除。现在按文件的实际存活目标连接唯一身份，跨未选 revision 时仍使用正确的旧路径和最终新路径，报告及上线说明保留重命名关系。
2. **目录复制加子文件改名漏交付副本**：原先只统计明确重命名或删除来源，漏掉与重命名同时存在的目录继承副本。现在一并保留分叉关系，跨选中端点时按真实路径规划删除/新增/修改；排除其中一个目标不会改变身份歧义。普通目录移动的自然后缀仍存在时，额外复制保持独立。
3. **新复制目录内的替换阻断独立文件**：SVN 可以将同 revision 内先继承、再重建的节点记录为 `R`，但目标在真实 r-1 并不存在。现在按新增处理该节点，最近的显式重建或嵌套复制截断父目录来源继承，不再查询虚构的旧端点。目录复制产生后又删除的临时文件也不进入交付。

实现位于 `vcs/multi_version_vcs.py`。历史身份规划仍在业务排除之前，来源匹配按路径祖先查询，不引入文件数与目录数的笛卡尔扫描。
