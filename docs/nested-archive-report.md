## 边界

当前源码支持 Git、SVN、文件夹、压缩包、Git多版本、SVN多版本，以及六种模式混合的多项目任务。
“递归查看压缩包内部差异”默认关闭、按来源记忆，每个多项目任务保存自己的选项。
旧配置缺字段按关闭处理；Git/SVN 家族的 true 选项正常保存和恢复。

交付清单、顶层变更计数和上线说明不变。`FileDiff.archive_details` 是报告子树，
不加入 `DiffResult.files`；`FileExporter` 不读取这棵子树。
文件夹中 `server.tar` 有变化时依旧交付完整的旧/新 TAR；直接比较两份 TAR 时，
仍按旧模式交付 TAR 中的变更成员，例如整个 `app.war`，不会继续拆开它。
不编辑、不重新压缩包；包内删除绝不成为宿主文件系统的删除指令。

## 比较及展示

按实际内容识别 ZIP、TAR、GZIP 和 gzip/bzip2 压缩 TAR，不依赖成员扩展名。普通 GZIP 解压为一个文件，支持 ODS `.dat.gz`、空数据和串接 GZIP 流。单文件名取外部名称去掉 `.gz`，无该后缀时追加 `.unpacked`，不采用压缩头中可伪造的 FNAME。
包内普通文本即使叫 `aaa.tar.gz` 也直接显示文本差异；普通二进制保留二进制展示。识别到 RAR、7z、XZ 时注明未展开；识别到真实压缩格式但结构、CRC 或长度损坏时仍记录分析失败，不回退成文本。最外层“压缩包”模式仍要求有效受支持的归档。
GUI 主流程直接借用已完整导出但尚未提交的暂存文件，分析实际交付字节，不重新读取仓库或工作副本。相同包字节不继续展开；仅属性变化或重命名仍保留。
变化包的成员先按当前引擎比较，再只进入其中变化的受支持内层包。
新增/删除包与空包比较；同包内重命名沿用唯一字节匹配，跨包不推测移动关系。
包原始字节变化但无可展示成员差异时明确标注，不能把父包变更删掉。

报告左侧只列交付文件；带“包内差异”的条目在右侧逐层展开。
每层单独显示成员计数，文本有左右对照及上一处/下一处；CLASS 仍是二进制，不反编译。
包内正文可点击或用 Tab 聚焦后按左右方向键横向滚动；鼠标点击局部上一处/下一处后，
焦点返回该成员正文。键盘用 Enter/空格操作定位按钮时保留按钮焦点，便于连续跳转。
明细在 HTML 生成时已完整写入；浏览器用 template 延迟实例化折叠明细，不是联网加载。

生成端使用显式栈按深度优先顺序产生层级事件，Jinja 逐片段输出，不再递归 `include`，
也不通过宏在内存拼出整个包的 HTML。分析端同样使用显式栈，父层 VCS 与空包上下文
保留到子层结束；成功、严格失败和中断均逐层关闭，不提高 Python 递归上限。
单项目和多项目共用同一模板；浏览器仍使用原有的 template 惰性展开与局部导航。
流式块大小、完整成员内容和转义回归见 `tests/test_rendering_performance_regressions.py`，
可重复内存测量见 `tools/benchmark_performance.py`。

## 排除、资源与错误

包内排除规则在每层包的根目录重新匹配，只影响该层审查；不会改写交付包内容。
外层被排除则不进入。忽略外层单一文件夹仍仅作用于用户选择的最外层归档，
不能自动套到每层 JAR/TAR。报告说明排除范围，不能声称核验了被排除内容。

固定排除计划内的尾随点/空格名称不落盘，仅保留逻辑名称；不会因已排除的
`logs/weblog.` 无法创建 Windows 占位文件而阻断其他成员比较。正文完整读取、
CRC、重复项及共享预算校验仍保留，路径穿越、ADS、保留名和链接仍拒绝。
未被排除的此类名称仍报错，完整规则见 [名称合同](report-and-export-contract.md#文件与目录名称)。

`archive_report._ReportArchiveVCS` 复用既有安全解压器，不使用无过滤 extractall。
保留路径穿越、链接、Windows 路径碰撞、包损坏及 CRC 等拒绝策略。
名称逐字一致且正文、相关文件属性一致的重复普通成员允许完整校验后按一份比较，
明细分别注明旧/新侧的原始名称和份数；不是按名称或 CRC 猜测相同。
每一份仍计入共享计数及显式资源策略并验证可读性及 CRC，排除项也不能隐藏冲突；内容或属性不同、
大小写/路径别名碰撞仍失败。原始交付包不去重、不重压缩。详见 [兼容与验证记录](archive-duplicate-members.md)。
同一份报告的嵌套展开阶段共享成员及字节计数（多项目不重置）。
递归层数、累计成员数和累计展开字节默认不限；单包成员数、单成员大小、
展开量和压缩比同样默认不限，不因正常包规模大或耗时长而拒绝、跳过或截断。
计数包括两端，既统计声明量，也在读取成员正文时累计实际字节；排除后丢弃的正文同样计入。
部署方可显式注入资源上限，超过显式上限时明确失败；路径、成员类型、长度、
CRC、来源身份和实际 I/O 校验始终保留，不提交不完整结果。
RAR/7z 等未支持格式仍按普通二进制文件展示，不宣称已检查内部。
桌面入口显式启用尽量导出：受支持后缀对应损坏、加密、LFS 指针或不可解析内容时，逐包记录“包内分析未完成”，保留真实原包和主报告，继续其余包。严格 API 默认仍抛出异常。端点读取与发布字节基线校验失败不属于解析降级，仍不能发布被改动的交付物。

当前复用解压器逐层使用固定排除计划：所有成员保留安全名称校验和名称占位，
被排除正文完整读完校验后丢弃，只将保留正文写入私有临时目录，再筛选变化成员。
公共动态 setter 入口仍全量提取；不能把零字节占位当作可导出的内容。
不会无条件继续展开所有内层包，也不宣称 ZIP 成员全程免落盘。
新增功能增加分析工作量，不能把旧版约 30 秒基准当成开启递归后的性能承诺。
成功或失败均清理本次私有临时目录，不修改业务来源或历史交付。
