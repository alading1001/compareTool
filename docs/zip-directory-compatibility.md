# ZIP/JAR 空目录属性兼容

递归比较 `ehcache-core-2.10.9.2.jar` 内的 `sizeof-agent.jar` 时，
工具曾将 `META-INF/maven/` 及其两个子目录误判为特殊文件而中止。
真实条目名称以 `/` 结尾，大小与 CRC 均为零，`create_system=3`，
但 `external_attr=0xFFFF0010`，高 16 位不是有效的 POSIX 文件类型。
原 JAR 的全部成员 CRC 检查通过；修复前的源码可直接复现同一错误。

`ArchiveVCS._extract_zip()` 仅兼容上述完整属性组合。兼容目录仍接受
路径与名称碰撞校验，读取本地头和空正文，不恢复 `0xFFFF` 权限，也不
修改或重压缩源归档。真实符号链接、FIFO、socket、设备文件、其它未知
属性、非空伪目录和损坏本地头继续失败。规则按元数据识别，不按文件名、
依赖名称或 `META-INF` 前缀放行。

专项回归入口为 `tests/test_zip_directory_attributes.py`：

- ZIP/JAR/WAR/EAR/AAR 的普通提取与固定排除计划，正文及文件权限保留。
- ZIP → TAR → JAR → JAR 的实际生成工作线程，递归报告包含末层正文。
- 递归开关前后主统计、导出字节和上线说明一致。
- 未知类型、真实特殊类型、路径越界和本地头损坏继续拒绝。

2026-10-11 的原包复现证据和独立输出保存在
`.tmp/zip-metadata-20261011/`，原始业务归档不纳入测试源码。
源码验证与发布 EXE 验证分别记录，不能用源码成功代替已安装程序更新。
