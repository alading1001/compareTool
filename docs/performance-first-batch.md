## Windows 文件夹扫描后续优化（2026-09-25）

针对“目录中文件很多、实际只改少量文件”的场景，继续优化 `path_safety.py` 与 `vcs/folder_vcs.py`。没有取消读取前后身份复核、源树最终复核、目录 junction 拦截或 FileId 校验。

主要调整：

1. 当前 Windows Python 的一次 `os.lstat()` 已包含 `st_reparse_tag`，不再对同一路径连续调用 `islink / isjunction / lstat`。
2. Windows 文件使用 `FILE_FLAG_OPEN_REPARSE_POINT` 直接打开最终路径组件，再从句柄校验 reparse tag 和 FileId；去掉打开前重复的路径查询。
3. `regular_file_path_identity()` 复用同一次安全打开取得的初始句柄身份，不立刻重复取第二次相同身份；实际内容读取前后仍由调用方重新取句柄身份。
4. 文件夹快照遍历时，普通文件的最终 link 检查延后到随后的安全身份打开，避免在同一阶段检查两遍；目录仍在进入前检查，防止遍历 junction。
5. 每个 `FolderVCS` 实例缓存比较根的 `realpath`，但每次文件访问仍重新计算目标 `realpath`，所以运行期间新插入的中间 junction/symlink 仍会触发越界检查。

### 文件夹扫描基准与验证

固定模拟数据：旧/新目录各 300 个 Java 文本文件，每个 80 行，其中 30 个文件只修改一处；每轮新建独立 `FolderVCS`，计时覆盖目录捕获、内容比较、变更端点快照和源树最终复核，不包含 `DiffEngine` HTML 渲染与最终交付事务。

- 优化前（三轮中位数）：5.554715 秒。
- 优化后（三轮中位数）：1.692621 秒。
- 该样本扫描阶段耗时降低约 69.5%，三轮结果均为 30 个变更文件。

另用真实 Windows junction 做隔离探针：`is_link_or_junction()` 正确识别 junction，`FolderVCS` 在进入该目录前明确拒绝遍历。目标文件的 `realpath` 越界检查、FileId 检查和读取前后身份复核均保留。

新增 `tests/test_folder_scan_optimization.py` 6 项回归，覆盖单次 lstat 快路径、name-surrogate reparse 判定、初始句柄身份复用、根 realpath 缓存、目标 realpath 每次重算，以及文件 leaf 检查由安全身份打开接管。最终完整回归：**411 项，410 项通过，1 项因当前 Windows 账户无创建符号链接权限而跳过，0 失败、0 错误**。
