# 文件夹扫描后续优化：保留准确性校验

日期：2026-09-27。优化前基线为 `0ebaba5f8934bf919a61870f8dacd205fa5fc20e`。
源码优化完成后，已按用户授权打包 `dist/CompareTool.exe`，并完成真实窗口的文件夹三轮验收、
六模式单项目及混合总报告验收，见 [2026-09-27 EXE 验证记录](release-20260927-verification.md)。
用户安装目录 `D:\java\applications\CompareTool` 中的 EXE 未替换。

## 修改范围

1. `path_safety.py` 将 Windows ctypes 结构定义和 API 签名绑定移到模块初始化阶段。
   使用独立 DLL 实例和线程局部错误码；每次查询仍创建独立结果缓冲区，实际调用 Windows API。
   文件类型、卷号、FileId、大小、时间和 reparse tag 没有缓存。
2. 相对路径拆分和字符校验使用最多 8,192 项的纯函数缓存。缓存保存不可变元组，公共接口仍返回
   独立列表。原路径、校验策略和错误标签共同作为键，大小写和短名称策略不会混用。
   8,192 是缓存条目预算，达到后淘汰旧项，文件数量和路径输入范围没有收紧。
3. `FolderVCS._walk_tree()` 每个目录只计算一次相对前缀，其下条目复用这个字符串。
   目录遍历、排除规则、目录拓扑和文件清单保持原有含义。

## 保留的准确性与边界检查

- 每次访问仍重新解析目标 `realpath` 并判断是否在比较根内；只缓存原有的比较根解析结果。
- 普通文件仍以 `OPEN_REPARSE_POINT` 打开，按句柄判断类型和身份；归档的禁止写入/删除共享模式不变。
- 源文件读取前后仍查询当前身份，读取结束后仍核对路径所指对象；实际文件内容仍分块比较。
- 快照完成后仍重新遍历整棵源树，核对路径集合、目录身份以及所有纳入比较的文件身份。
  未复制的未变化文件也要复核；同大小、同时间戳替换不能绕过 FileId 检查。
- 变更端点快照、导出字节、递归报告的交付 stage 绑定、输出路径边界和批次互斥不变。
- 原生 API 失败仍使任务失败，不转为空文件、假身份或成功结果。

本轮没有把目录枚举结果用作跨阶段的身份缓存，也没有替换 Python 的真实路径解析流程。

## 验证方式

新增 `tests/test_folder_scan_followup.py` 验证：缓存结果不能被调用方修改污染、短名称策略独立、
大小写不同的根不混用、Unicode 路径与排除拓扑不变、未复制文件的同大小同时间戳替换仍失败、
并发身份查询缓冲区独立、禁止写入/删除仍有效、原生 API 错误仍上报、缓存预热后插入 junction 仍拒绝。

完整回归在独立源码副本执行，避免测试夹具影响工作区。测试日志、计时和摘要证据保存在
`.tmp/scan_followup_20260927/`；验收后的源码副本、测试输入及重复导出已按用户要求清理。

真实目录基准通过 `tools/benchmark_folder_worker.py` 调用实际 GUI 的生成工作线程，关闭包内递归、
不排除文件、显示全部正文并保留 oldVersion/newVersion 导出。优化前后交替各运行三次，
每次写入项目诊断目录中新建的独占输出目录。

计时包含空目标检查、扫描、内容比较、变更快照、最终源树复核、完整报告、导出、发布和清理，
不包含事后的报告与交付物核对，也不包含删除大量旧输出的耗时。每轮核对全部导出文件路径、
字节长度和 SHA-256，以及报告左右正文与上线操作说明；只比较耗时不算验收通过。

## 重复执行

```powershell
.\.venv\Scripts\python.exe -B tools\benchmark_folder_worker.py `
  --old '<旧文件夹>' --new '<新文件夹>' `
  --baseline-source '<优化前源码副本>' --source-root . `
  --output-parent .tmp --repeats 3
```

工具不会复用或清空既有输出目录。加 `--profile` 可单独诊断调用耗时，但该轮带有 profiler 开销，
不能混入普通基准数据。源码工作线程验证不等于新 EXE 验收，也不能推导所有磁盘、NAS 或其他 VCS
模式具有同一提速比例。
