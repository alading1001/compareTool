## 范围

- 包含本地项目内的源码、文档、Git 元数据、历史构建、虚拟环境、个人配置、日志及 `.tmp` 的实际文件内容。
- 本机 `.tmp` 是指向 E 盘的 junction；归档将其内容保存为普通 `.tmp` 目录，恢复时不依赖原 E 盘路径。
- 仅排除本次备份工具及其输出目录 `build/cloud-migration-20261106/`，避免把正在生成的归档再次归档。恢复工具、逐文件清单和 SHA-256 校验清单随私有 Release 单独提供。
- 这是项目文件备份，不是操作系统映像；Windows ACL、备用数据流及原 junction 布局不属于恢复目标。

## 恢复

1. 登录有权限访问私有仓库的 GitHub 账号，下载同一次备份 Release 的全部分卷、清单和恢复工具。
2. 按附件中的恢复说明核对所有分卷 SHA-256，再恢复到新的空目录。
3. 恢复工具逐文件核对内容 SHA-256、数量及大小；确认成功后再使用其中的源码和资料。
4. `.venv` 可作为历史资料保存，云端运行时应按项目依赖重新创建环境。GitHub 云端开发以最新源码分支为准，正式 EXE 验收仍需 Windows。

不要将私有备份附件转存到公开仓库。完整备份的最终状态以该次私有 Release 的附件及校验结果为准，建立备份不等于已授权删除本地文件。
