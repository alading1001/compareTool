# Git/SVN 多版本文件端点设计

- 状态：已实现并通过测试
- 首次确认及实现日期：2026-08-24；最近冲突降级与尽量导出验证：2026-10-13
- 适用模式：Git多版本、SVN多版本

## 实现状态与边界

`vcs/multi_version_vcs.py` 已使用文件身份追踪和文件级端点快照替代遗留的统一基线重放算法。它不再执行 Git cherry-pick 或 SVN merge，也不会修改真实项目目录。

界面名称已经统一为“Git多版本 / SVN多版本”；内部配置值仍保留 `git_multi` / `svn_multi`，旧多项目任务中假的“基线 + 选中版本”会在加载时迁移为“文件级首尾端点”。

## 唯一目标语义

选中版本只负责两件事：

1. 决定哪些逻辑文件进入候选集合；
2. 为每个文件分别确定首次和末次选中变更。

对每个逻辑文件 `f`：

```text
S_f = 所有选中版本中，真正修改过 f 的版本集合
first_f = S_f 中历史最早的版本
last_f  = S_f 中历史最晚的版本

old_f = f 在 first_f 发生之前的真实状态
new_f = f 在 last_f 提交之后的真实状态
报告  = old_f 与 new_f 的最终净差异
```

- Git 只支持当前分支第一父历史；`old_f` 来自 `first_f` 的第一父提交，`new_f` 来自 `last_f`。
- SVN 按 revision 排序；`old_f` 来自 `first_f - 1`，`new_f` 来自 `last_f`。
- 不使用当前工作副本或 HEAD 代替 `new_f`，因为它们可能已包含更晚版本。
- 不使用全局最高选中版本强制读取所有文件；不同文件允许来自不同版本。
- 不重放提交、不三方合并，也不制造历史中不存在的合成文件。

## 已确认场景

```text
r3 修改 B.java（选中）
r6 修改 A.java（选中）
```

结果允许为：

```text
B.java：old = B@r2，new = B@r3
A.java：old = A 自己首次选中变更前的状态，new = A@r6
```

若同一文件在 r3、r6 均被选中版本修改，而中间 r4 未选中：

```text
old = 文件@r2
new = 文件@r6
```

r4 不单独展示，但它对该文件最终状态造成的净影响会自然出现在首尾差异中。选择 r6 表示认可 r6 提交时该文件的完整真实状态；若 r4 内容不应上线，应在 r6 中先回滚或修正。

若 r4 未选中，r6 是选中版本中第一次修改该文件的版本：

```text
old = 文件@r5
new = 文件@r6
```

只展示 r6 相对其前一版的净变化。

## 净结果规则

中间修改、删除、恢复和重新新增只用于确定路径对应关系，不展示历史过程：

- 左侧不存在、右侧存在：新增；
- 左侧存在、右侧不存在：删除；
- 路径相同、内容不同：修改；
- 起始路径与最终路径不同：重命名，内容仍按首尾状态比较；
- 路径和内容最终均相同：净零变化，不进入报告和导出。

改名可能发生在未选中的中间版本。只要后续选中版本继续修改改名后的路径，就以首次选中变更前的旧路径作为左侧，以末次选中变更后的最终路径作为右侧。报告只显示首尾改名，不展开中间路径历史。

Git 选中提交覆盖从最早到最晚的完整第一父历史时，每一步的删除、新增和重命名都被选中，最终路径状态可以直接由这些真实变更确定。此时保留 Git 原生识别的重命名及明确的删除/新增，不再对不同逻辑文件执行额外的候选配对或歧义拒绝，避免连续依赖升级被删除/新增矩阵误拦截。仍逐提交确定每个文件的首次/末次端点及其属性、模式和字节，不把所有文件强制读为全局最后版本。版本输入顺序、重复项及短/完整提交号不影响连续性判断；中间只要存在未选中的提交，仍执行原有完整身份歧义检查。

## 身份冲突降级（2026-10-12）

身份不确定不阻断报告。候选两侧跨越选中端点时，收集全部冲突组，并按共享实体及路径生命周期形成连通组。每组取最早选中事件的前状态和最后选中事件的后状态，逐一查询组内全部真实历史路径；两侧不存在的中间别名不导出。以路径配对产生 D/A/M，禁止再按内容合并 R。没有冲突的文件仍使用各自端点，不能强制读成全局最高选版。

文件与目录互换的生命周期同时包含旧后代和新子文件；按完整路径分量沿祖先索引关联，不连接无关兄弟。目录只作为文件容器，不占据文件端点。SVN 分叉中旧文件名被目录复用时必须保留新子文件，目录被分叉目标文件覆盖时必须保留真实旧后代删除及必要目录操作，不能因中间替换未选中而漏项。见 `tests/test_history_endpoint_projection.py`。

Git 路径查询中的 tree 目录只作为文件容器，不作为该路径的文件端点；目录与文件互相替换时，保留子文件的 D/A、对应文件的 A/D 及必要目录删除依赖，不能把目录与子文件误判为同侧端点碰撞。符号链接、子模块等非普通文件仍保留端点并由既有 mode 校验拒绝。

辅助低阈值 diff/评分失败也只降低该候选组的身份判断；真实路径存在性、普通文件模式、属性及流式端点字节必须另行验证。桌面应用对不能验证的独立端点记录未完成，并继续其他文件；严格 API 仍可拒绝这些端点。报告的比较说明和上线说明记录降级。

## 报告与导出合同

报告和导出必须使用同一组文件端点，不允许报告一套、oldVersion/newVersion 另一套。

```text
oldVersion/<old_path> = old_f 的完整文件内容
newVersion/<new_path> = new_f 的完整文件内容
```

- `newVersion` 中是可直接阅读或覆盖对应路径的完整源码/二进制文件，不是补丁片段。
- `newVersion` 是不同文件各自末次选中版本状态的集合，可能混合多个 revision/commit；它不是某一个版本的完整项目源码快照。
- 删除文件只进入 `oldVersion` 和删除清单；新增文件只进入 `newVersion`；重命名使用旧路径导出 old、最终路径导出 new。
- 编码、BOM、换行符和二进制字节遵守 [报告与导出完整性合同](report-and-export-contract.md)。原始与检出端点均须排他创建，实际 Windows 文件或目录短别名碰撞时拒绝冲突各方；桌面入口列未完成并继续独立文件，严格 API 可中止，不得覆盖另一个逻辑文件。

每次生成还必须在报告、`oldVersion` 和 `newVersion` 同级生成带 UTF-8 BOM 的上线操作说明：单项目使用 `<项目名>_上线操作说明.txt`，多项目使用 `上线操作说明.txt`，避免同一批次内多个单项目相互覆盖：

- 列出需要删除的旧路径；重命名的旧路径也进入删除清单；
- 单独列出 `旧路径 -> 新路径` 的重命名关系；
- 多项目路径始终带项目名，不受报告展示选项影响；
- 即使没有删除或重命名也必须生成，并明确写“无”；
- 报告详情和弹窗路径清单默认完整生成，不因预计文件数、路径字节或 HTML 体积降级/截断；最终报告流式写入临时文件并原子替换，默认不设体积上限；
- 确认覆盖后先删除本次项目旧输出，再生成完整的新报告、说明和两套导出，失败不恢复旧结果。输出批次锁覆盖整个过程；具体约束见 [报告与导出完整性合同](report-and-export-contract.md#覆盖与重新生成)。每次多项目生成使用独立运行目录。

## 实现要点

当前实现继续复用：

- DiffEngine 的文本、格式和二进制差异；
- FileExporter 的完整字节导出和完整结果发布；
- 临时 old/new 快照目录；
- 排除规则、多项目总报告和版本列表多选交互。

端点规划保留每个文件自己的 `old_version`、`new_version`、`old_path` 和 `new_path`。重命名并修改内容不会退化为两个互不相关的删除/新增记录。

- Git：只分析当前分支第一父历史，合并提交相对第一父提交计算；父对象在浅克隆边界缺失时中止。连续选版按上述净结果规则处理；非连续选版先以正常重命名阈值追踪身份，并用紧凑路径组保存同提交 `D/R → A/R/M` 竞争结构；所有文件级端点确定后，只有不同逻辑实体真正跨越选中端点时才运行低阈值第二遍 diff 或逐对评分，每个命中组均记录降级，不能在首个冲突后漏掉其余组。跨提交只保存待定删除活动区间和后续 `A/R/M` 目标事件，按 `start < target_step <= end` 与最终选中步过滤后才评分，不在历史遍历阶段展开乘积。需要评分时把 source/target blob 流式写入隔离临时目录，用 `git diff --no-index --find-renames=50%` 重算 Git 原生分数；历史规模、候选矩阵、评分次数和评分字节默认不设性能型硬上限。候选身份跨越选中端点且不能唯一确认时按上述冲突组路径端点降级，不猜测 rename。
- SVN：解析当前项目 URL 的 `svn log --xml -v` 历史，用 `copyfrom-path`、revision 对应的项目仓库前缀和删除覆盖关系追踪身份。项目根、祖先或嵌套目录移动，同 revision 子文件改名、移出目录、覆盖已有目标，延迟 copyfrom 和移动后删除源祖先都要保持同一逻辑文件；普通 copy 的源仍存在时保持两个独立文件，同源多目标且自然后缀消失时降级为删除源和新增各目标。
- 两种模式：历史身份及分叉规划独立于业务排除；真实首尾端点确定后、新旧正文读取前逐侧过滤，旧侧排除为 A，新侧排除为 D，双侧排除跳过。中间排除路径不切断身份，排除 copy 目标不改变分叉判断。项目范围边界仍先于身份竞争；目录剪枝仅适用于不需要该历史元数据的扫描，不能跳过身份关联。导出字节与仓库原始字节分别流式快照到磁盘，前者供 oldVersion/newVersion，后者用于识别 BOM、编码和换行符净差异，净零判断使用分块文件比较，不同时保留四份内容。默认不为了预计写盘量额外查询所有端点大小，也不设端点文件数、源字节或预计写盘量的性能型固定上限；实际端点读取或写盘失败时，严格 API 中止；桌面入口拒绝该文件两侧并记录未完成。SVN log/list 使用增量 XML 解析且默认不限制生成命令输出体积；目录覆盖、移动和排除前缀使用前缀索引或路径层级查询，不能形成文件数×目录数的重复扫描。Git 的 commit、检出配置和有效属性固定后再读取；SVN 的 URL、仓库根、UUID 与 peg revision 由同一次 XML info 固定，历史上界不得再使用可变 HEAD。Git 历史中的类型变化只延续同路径身份，不因无关中间文件全局失败；最终选中端点出现非普通 mode、`svn:special` 或其它非普通文件时，必须在净零过滤前拒绝该文件；桌面入口记录未完成，严格 API 中止。成功或失败后都清理临时目录。
- 交付暂存：新内容直接位于可信输出根，单项目源码使用随机 wrapper，多项目在外层 stage 内逐项目生成，全部完成后发布。没有旧输出备份或签名恢复，路径隔离和本次已分析字节绑定仍须保留。

## 验收底线

自动化验收覆盖：

1. 不同文件使用不同首尾版本；
2. 同一文件跨选中和未选中中间版本；
3. 未选中改动发生在该文件首次选中变更之前；
4. 中间改名以及改名同时修改内容；
5. 新增、删除、删除后重建；
6. 多次选中变更最终完全抵消时不输出；
7. Git 当前分支第一父约束；
8. SVN 文件和目录移动；
9. 空文件、二进制、编码、BOM 和换行符；
10. 报告左右内容与 oldVersion/newVersion 导出字节完全一致；
11. Git 浅克隆缺少父对象时拒绝项目；跨选中端点的低相似重命名、重复/高相似竞争来源、跨提交移动和同路径重建噪声按冲突连通组真实路径端点降级，其他文件保留自身端点；无关中间低相似重命名和类型变化不阻断；
12. SVN 项目根/祖先/嵌套目录移动、同修订子文件改名、移出目录、覆盖已有目标、延迟 copyfrom、源祖先删除、普通 copy、同源多目标，以及目录移动同 revision 的普通子文件 copy；
13. 多项目任务旧配置迁移，不能继续保存假的“基线 + 选中版本”；
14. 单/多项目确认覆盖后清除本次旧结果；独立文件或项目失败记录未完成，其余继续；无法安全写入或发布时失败且不恢复，无关项目和历史运行目录保留；
15. 多版本界面与单项目报告使用“选中版本 / 生成结果”，不得伪装成统一“旧版本 / 新版本”；
16. 真实 NTFS 文件及目录短别名碰撞时拒绝冲突路径；严格 API 失败，桌面尽量交付可验证文件并列明未完成。独立合法的 `~` 路径仍可使用；已确认删除的旧输出不恢复。
17. 业务排除只投影最终真实端点，不删除中间历史身份或 copy 竞争目标。先移入排除目录再移出仍追踪同一文件；真实分叉保留 D/A/M，不能因某个目标排除而猜测唯一 rename。跨未选版本和连续未选分叉按文件级因果组重新规划，不能残留中间旧路径；只有一侧参与选中的无关 copy 不扩大候选集合。文件/目录替换先区分两侧，目录替换不得间接删除被排除的旧后代。快照固定后更改规则必须新建任务。回归见 `tests/test_history_endpoint_projection.py`、`tests/test_exclusion_path_flow.py`、`tests/test_svn_exclusion_move_boundaries.py`。
18. SVN 同 revision 的多个目录 copy 必须按每个文件实际存活的目标确认身份：其它副本已删除时连接唯一目标，不得重新导出消失的源路径；显式子文件改名和另一个继承副本同时存在时保留全部分叉目标，排除规则不能改变判断。最近的显式重建或嵌套 copy 截断父目录来源继承；新复制目录内的临时删除、替换节点在真实 r-1 不存在时，不得虚构旧端点或阻断独立文件。回归见 `tests/test_svn_copy_lineage_review.py`，同时核对报告、manifest、导出字节及上线删除/重命名说明。

主要回归用例位于 `tests/test_multi_version_file_endpoints.py`、`tests/test_review_regressions.py`、`tests/test_adversarial_regressions.py`、`tests/test_terminal_round_adversarial_regressions.py`、`tests/test_complete_export_review_fixes.py`，以及五个 `tests/test_*_compatibility_after_aug27.py` 兼容性套件。

## Git 子项目范围

用户选择仓库子目录时，只规划这个子项目中的文件，排除规则和交付路径均相对于所选目录。对象、属性和文件 mode 查询会映射回仓库根相对路径。每个历史步先应用项目边界，再参与身份竞争：移出记作删除，移入记作新增，内部重命名继续追踪。禁止将同一仓库的兄弟项目变更装入当前项目的源码包。裸仓库保留根范围导出支持。
