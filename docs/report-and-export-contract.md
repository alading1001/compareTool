# 报告与导出完整性合同

本文件是差异展示、字节导出和输出完整性的详细约束。修改 `diff_engine.py`、`stable_diff.py`、`report_generator.py`、报告模板、`file_exporter.py`、`path_safety.py` 或 VCS 端点写入流程前，须与 [AGENTS.md](../AGENTS.md) 一起阅读。多版本文件身份与首尾语义另见 [多版本文件端点设计](multi-version-file-endpoints.md)。

正常输入允许耗时生成，默认不因预计工作量拒绝、截断或跳过。归档成员数、单成员大小、展开量、压缩比及递归层数均默认不限；累计计数继续保留，资源上限仅在显式注入策略时生效。无法确保路径、字节或新结果完整性时必须失败，不能交付看似成功的错误结果。

## 尽量导出（2026-10-12）

桌面应用六种模式及混合任务均默认尽量输出，并区分“已导出”“含处理说明”和“含交付未完成项”。下层比对、解压、导出 API 默认严格检查；桌面入口显式启用 `best_effort`。不因规模或耗时省略正常结果。

- 重命名身份冲突改用真实路径端点，不再整次拒绝。组内各路径 old 取首次选中变更之前、new 取末次选中变更之后；旧侧独有为删除、新侧独有为新增、同路径为修改或净零。组外文件保留自己的首尾端点，不二次配对为 rename。
- 内容展示或辅助精确 rename 检测失败只记录说明；包内解析失败逐包标记未展开，保留已验证的原包；递归仍绑定本次导出 stage，不改用 raw、工作副本或下载 LFS。
- 独立文件的端点/转换/导出失败记录未完成项，该文件两侧都不交付；路径碰撞双方都不写。独立项目读取失败保留诊断记录，其他项目继续。主清单、统计、manifest 和上线操作只引用实际成功交付项；未完成路径和原因在报告顶部及上线说明单独完整列出。
- 文件与目录双向替换均属于同一依赖组：旧目录后代与新文件、旧文件与新目录后代必须一起交付。VCS 在端点类型、属性及正文验证之前保存范围和排除投影后的路径拓扑，失败项不能从依赖推断中消失。任一项失败（含前阶段未完成记录）时整组退出交付和上线操作；依赖根独立于实际目录删除指令，文件变目录不能生成删除旧目录指令。失败重命名的诊断必须保留有效旧路径，让依赖检查同时覆盖新旧两侧。目录匹配按 Windows 键比较，上线说明保留旧侧拼写。
- 同一文件路径的复用也属于交付依赖：例如 `a → b` 后另行新增 `a`，任一项端点读取或导出失败，相关项必须一起退出交付。新旧路径按 Windows 键关联，并与目录替换依赖传递闭包；不能只剔除失败 rename 后，仍导出会覆盖其旧路径的新增文件。独立文件继续，全部成功时保留原有 A/R 语义与完整端点。
- 尽量导出为成功端点记录文件身份与内容摘要；部分失败后复核剩余端点及实际暂存清单，不能把此前已写入但后来被替换或篡改的内容发布。实际短名碰撞以已存在方定位冲突组，双方均退出；清理前复核该项仍属于本次。
- 先完成导出，再生成报告和说明。模板失败时输出不依赖模板的基础清单报告；包根忽略选项结构不满足时两侧一起退回完整包路径；多项目展示路径冲突自动补充相关项目名前缀，不改保存的任务设置。
- 输出根边界、输入隔离、锁、暂存所有权、字节基线和发布目标仍严格校验。不能安全写输出或发布时仍报错，不覆盖外部新目标。空文件正常导出，真实读取失败不能替换为空内容。
- 耗时记录 `status=partial` 表示生成了含交付未完成项的报告；`success` 只表示报告任务完成，不表示文件全部交付。`counts.delivery_incomplete/failed_items/issue_count` 与完成提示一致。

## 覆盖与重新生成

2026-09-27 用户明确确认：报告和导出可以重复生成，确认覆盖即允许丢弃上一份结果。因此旧输出备份、HMAC 恢复日志、回滚和跨阶段旧内容摘要检查已退役，后续不得依据历史设计重新加回。

确认覆盖后，先在输出批次锁内删除本次项目的旧报告、上线说明和 oldVersion/newVersion 下的该项目目录，再开始比对与生成。失败不恢复旧结果，已经删除的部分也不恢复。只删除经过输入隔离、可信根边界、真实 Windows 名称及类型校验的明确目标；不清空整个输出根，不删其他项目、手工文件或输入源码。删除失败就报错并停止本次生成，不假装覆盖成功。

锁从删除开始一直持有到生成、发布和清理结束；同批次第二个实例在删除前报忙，进程退出后系统自动释放锁。固定锁文件拒绝链接、联接点、硬链接及打开期间的替换。耗时生成期间被其他程序重新创建的正式目标不再作为旧结果删除，发布应失败并保留它。

内置 VCS 仍通过 export_file_to_path() 流式导出完整端点字节；空文件正常导出，读取、转换或写入失败不能静默漏文件，桌面入口将失败文件列为未完成。新报告、说明和源码先写入用户配置的可信输出根中的私有暂存项，全部生成完成后发布，报告最后安装。捕获到失败时清理本次暂存及可确认仍属于本次的已安装产物，不恢复上一份结果，不创建 journal、备份、commit/rollback 标记或私钥。进程被强制终止可能留下本次部分输出或暂存物，下次重新生成即可；没有跨进程恢复承诺。

Windows 发布 `rename` 遇到 WinError 5/32/33 时，允许对同一暂存项最多重试 4 次，依次等待 0.1/0.2/0.4/0.8 秒（合计等待 1.5 秒，不含操作和校验耗时）。正常成功不等待，其他错误立即失败；不重新解压或生成，不改用覆盖、删除目标或复制回退。每次等待后重新校验可信路径、暂存对象身份及正式目标仍不存在；已绑定包内分析的暂存项还须对照原内容基线复核，不更新基线。最终失败提示发布阶段、目标路径和原始错误；恢复成功只记一条重试日志，沿用日志容量限制。

启动和生成均不读取、校验或执行历史恢复记录；旧记录及残留备份原样保留，不因签名失效阻断新任务，也不凭其中的路径删除文件。历史遗留物的人工清理需单独明确范围。

多项目仍在独立 multi_run_时间戳_随机标识 目录内生成，处理完全部项目后发布带准确状态的本次结果，保留其他历史运行目录。失败项目保留问题记录，其他项目继续；存在未完成项时必须明确标记部分交付。重命名 oldVersion 使用 old_path，newVersion 使用 file_path。

多项目预检遇到已保存的 Git 项目目录失效时，将仓库身份读取失败保留为该项目的未完成记录，继续其他独立项目。输出仍须与失效输入路径严格分离；若仍存在祖先 Git/SVN 仓库，继续检查其已跟踪路径、元数据和嵌套仓库边界。真实输出冲突或无法完成这些输出检查仍中止整批；本次已判定不可读的项目不能因稍后目录恢复而绕过预检重新读取。界面与工作线程复用同一规则。

上述同路径依赖、同 revision 重命名及失效项目隔离回归见 `tests/test_review_path_dependencies.py`，包含实际工作线程的文件字节、报告、上线说明与危险输出拦截检查。

压缩包“忽略最外层单一文件夹”的比较根、报告路径、权限元数据、排除、导出和上线说明仍必须一致；不满足根目录结构时两侧均回退完整包路径并说明。固定提取排除计划须先收齐两端结构，再成对确定比较根、保留正文和空间估算；不能在丢弃正文后才切换根目录。结构回退不放宽路径、成员类型、CRC 或重复成员检查，严格 API 仍拒绝不适用的根结构。

## 差异展示

`DiffEngine.__init__` 接收 `show_full_context` 参数（由 GUI 单选按钮控制）。`True` 时展示文件全部行（`context=False`），`False` 时仅展示差异上下文（`context=True, numlines=3`）。默认为全部内容。

`HtmlDiff` 递归失败时由 `stable_diff` 按行序配对替换段，保留全部内容和行内差异，继续遵循用户选择的上下文范围；不能通过提高递归上限或截断输入应付。未知编码用 `surrogateescape` 保留字节身份，先匹配再显示带底色的 `⟦0xXX⟧`，并以文件说明标注编码状态，不能用 replacement 字符合并真实差异。

用户的完整性原则是：对抗性审查不得让旧版本能生成的正常输入因“可能很慢/可能很大”而被拒绝、跳过明细或截断清单。正常文本默认不设单文件字节、行数、最长行、明细数、路径字节、文本字节、预计渲染行数和 HTML 字节上限，也不得使用新旧行数乘积、最长行字符乘积或组合工作量提前跳过。目录替换推断必须使用前缀树或等价的线性/近线性算法，不能枚举全部新旧路径笛卡尔积。读取返回 `None`、已知 raw 大小与实际读取长度不符、或源端点在任务期间变化时必须拒绝该文件或整个不稳定项目，因为继续会得到错误结果。Jinja2 必须流式写报告，不能先在内存中生成完整 HTML。纯格式变化和纯重命名仍须保留 F/R 语义。

报告补充合同：manifest 必须完整列出变更，不因预计体积截断；最终报告必须边渲染边流式写入同目录临时文件，成功后再原子替换，默认不设 HTML 体积上限。默认详情完整时 manifest 直接复用 `fileData`，不得把同一完整路径清单再次序列化；只有显式受限策略让二者不同时才生成独立清单。多项目展示路径在浏览器端拼接，不重复保存 `displayPath`。末尾换行格式净差异只允许在 CR/LF 规范化后两端恰好相差一个末尾 `\n` 时成立。差异拆行与统计也只识别 CR/LF，不能用 `splitlines()` 把 FF、VT、NEL、U+2028/U+2029 等分隔符吞掉；特殊分隔符参与真实字符匹配后才在 HTML 中显示为 `⟦U+XXXX⟧`，不改变导出字节，也不能与原文中的字面标记混淆。

文本含 SOH（`0x01`）时，新增、删除、修改和重命名均使用保留原字符的逐行渲染，避免与 `HtmlDiff` 的内部标记冲突。匹配完成后显示 `⟦U+0001⟧`，与字面标记通过专用 span 区分；全文、上下文及片段存储遵循同一规则，导出字节不变。

## 二进制文件处理

- `DiffEngine.BINARY_EXTS` 定义二进制扩展名集合（`.jar`, `.war`, `.class`, `.dll` 等）
- `DiffEngine._diff_file()` 对二进制文件提前返回，不读内容，`side_by_side_html` 设为占位提示
- 导出时所有文件（含二进制）统一走 `export_file_to_path()` 分块或子进程直写目标；Git/SVN 的换行转换也在同目录临时文件中分块完成，空文件正常成功，读取失败必须拒绝该文件并记录未完成，不能影响其他独立文件。
- Git 用固定 commit 的 `git show` 直写，SVN 用固定 URL/revision 的 `svn cat` 直写，Folder/Archive/多版本快照用分块复制；精确重命名匹配使用 blob OID 或分块 SHA-256，不得整文件载入内存。SVN 哈希临时文件必须使用 CompareTool 专用临时根，避免大型内容落到系统盘默认临时目录。
- Git 和 SVN 导出时按固定端点的换行符策略转换，使导出文件符合所选版本应有的检出字节；并非所有文本都转换为 CRLF（见换行符处理章节）。

## 文件与目录名称

Git 树路径中的字面反斜杠属于文件名，不能替换成 `/` 后读取另一对象或参与历史身份规划。排除规则按原始仓库层级匹配；最终未排除端点含反斜杠时，严格 API 拒绝，桌面入口记录未完成并保留其他独立文件。诊断保留原名，交付依赖仅使用可表示的路径侧，不能误关联合法的斜杠同名文件；失败 rename 的合法一侧仍阻断路径复用。中间历史经过该名称、最终端点均合法时可正常交付。

### 排除规则贯穿流程

规则匹配项目相对路径；递归明细在每层归档根重新匹配。项目目录、仓库身份、输入归档本身及输出根/锁/暂存的边界检查仍必须执行，不能把业务文件 glob 当作关闭这些检查的开关。

- 文件夹含固定目录委托，均先筛选再读取正文；完整排除的目录保留名称拓扑，不再打开其身份或后代。未排除节点仍执行原有源状态固定、前后身份及最终范围复核。
- 同一条 `.../**` 规则覆盖某个祖先时，其后代目录同样属于完整排除；`foo/*` 或不同规则拼接不构成任意深度剪枝证明。
- 普通 Git 先获取原生变更/重命名，再按新旧侧过滤；普通 SVN 先确定真实变更及文件/目录替换，过滤后读取内容，唯一完全相同文件的重命名合并属于展示判断。
- Git/SVN 多版本先按固定项目范围的完整历史追踪身份及复制分叉，确定文件真实首尾端点后再逐侧应用业务规则。中间经过排除目录不切断身份；排除某个 copy 目标也不能把真实分叉变成唯一 rename。旧侧排除为 A，新侧排除为 D，双侧排除跳过。SVN log/list 可读取被排除路径的身份元数据，Git 必要的身份评分可读取相关 blob；最终排除端点不生成正文快照、不导出。项目边界仍在历史竞争前应用。
- SVN D/A 分叉保留文件级因果关系；只有关系跨越选中端点时，按冲突组首次选中前及末次选中后的真实路径重新规划，支持连续多次未选分叉，不能残留中间别名。无关文件保留自己的端点。多版本快照生成后规则不可变，相同规范化 setter 幂等；更改规则必须新建任务，直接改列表也应在读取时拒绝。
- 文件与目录替换先区分真实新旧侧，过滤后仍核对双向依赖：新普通文件不能连带删除被排除的旧目录后代，新目录及子文件也不能隐式移除被排除的旧普通文件。相关替换整组记录未完成并退出导出和上线操作；严格 API 拒绝。只保留排除旧路径名称，不为依赖检查读取正文。
- 报告、manifest、导出和上线说明复用过滤后的交付集合；不在输出路径上再次按项目 glob 匹配。包内递归只筛选明细，不修改已交付原包。归档结构、安全边界、长度/CRC、重复成员一致性及全量资源计数继续校验。

回归入口：`tests/test_exclusion_path_flow.py` 覆盖六模式实际工作线程、混合项目独立规则快照、递归明细、历史跨界、目录复制竞争及文件/目录替换；`tests/test_svn_exclusion_move_boundaries.py` 覆盖原子目录移动与子文件改名、嵌套移动、移出及 copy 分叉的单侧排除；`tests/test_archive_excluded_trailing_names.py` 覆盖已排除尾随名称的读取校验和不落盘。

最终端点投影、未选分叉、规则冻结和六模式目录替换保护见 `tests/test_history_endpoint_projection.py`。旧 GNU sparse 扩展映射块在物理正文之前逐块消费，核对范围、重叠及物理长度；逻辑长度用于展开预算，映射块计入显式扩展元数据策略。无映射、单块、多块、截断和压缩变体及实际导出见 `tests/test_gnu_sparse_extensions.py`。

导出、多版本端点与文件夹快照写入前必须逐级校验真实目录项并排他创建文件，拒绝实际 NTFS 短别名碰撞，允许独立合法的 `~` 名称；路径型 writer 只可写入本次已占有的新目标。碰撞必须在调用覆盖写入接口前失败，不能让两个报告路径共享一个输出文件，也不能在失败清理时删除被碰撞的已有文件。

归档的固定排除计划在预检阶段即确定。已排除的成员若仅含 Windows 无法保真的尾随点/空格名称（如 `shepherd/logs/weblog/weblog.`），只保留逻辑名称，不创建该成员的磁盘占位，也不修剪名称后写盘；可保真的祖先目录占位仍保留，最外层目录结构不按排除结果重新猜测。该成员正文仍完整读取，ZIP CRC、长度、重复内容及属性、全量展开计数和显式资源策略照常验证。绝对/盘符/父目录穿越、ADS、保留名、链接与逻辑名称冲突仍拒绝。未排除成员和公共动态排除接口仍拒绝尾随点/空格名称；固定计划不能放宽，已排除成员不能读出或导出。此例外不修改原包及递归交付包字节。回归见 `tests/test_archive_excluded_trailing_names.py`。

ZIP 目录成员必须为空，非空目录拒绝；普通、兼容属性及已排除而不落盘的空目录均打开读取，核对本地头、加密标志及空正文 CRC。GNU sparse TAR 保留兼容解析与提取，固定排除及空间计划使用解析后的真实逻辑名称和长度，原始头名与逻辑名分别做路径校验；不能因包中包含 sparse 文件就关闭其他成员的固定排除，逻辑展开量仍按全量计入预算。回归见 `tests/test_archive_exclusion_review.py`。

归档中名称逐字一致的重复普通文件可以在完整读取后合并：每份声明长度、流式 SHA-256 及相关文件属性必须一致，ZIP 每份 CRC 仍由解析器校验。ZIP 比较来源系统、外部/内部文件属性；TAR 比较权限、uid/gid 和属主/组名。压缩方法、记录时间等容器存储信息不作为文件内容差异。只对实际重名候选计算额外摘要，第二份及后续正文校验后丢弃，不覆盖第一份，不重复写盘；有冲突时整次失败。大小写不同、不同路径写法归一化后相同、链接、文件/目录前缀及真实短名别名碰撞，不适用此例外。

普通压缩包比较与报告递归共用上述规则。排除不免除重名一致性检查；所有副本继续计入成员数、声明展开量和实际消费量，内容只消费计数一次。普通报告比较说明和递归明细注明合并重复项；递归明细保留旧/新侧原始名称和份数。递归原始交付包保持逐字节不变，普通压缩包模式仍导出唯一文件路径。回归见 `tests/test_archive_duplicate_members.py`，实际 Git 样本及验证记录见 [重复归档成员兼容](archive-duplicate-members.md)。

## 归档输入与临时目录

`ArchiveVCS` 通过 `vcs.temp_storage.create_temp_dir()` 解压两端，委托 `FolderVCS` 遍历和比较。ZIP 家族为 `.zip/.jar/.war/.ear/.aar`，使用 `zipfile`；TAR 家族为 `.tar/.tar.gz/.tgz/.tar.bz2/.tbz2`，使用 `tarfile`。ZIP 名称未设置 UTF-8 标志时，`_fix_zip_filename()` 将 CP437 解码后的名称还原为原字节，再按 GBK 解码。特殊空目录属性的精确允许条件见 [ZIP 目录属性兼容](zip-directory-compatibility.md)。

构造时先同时捕获并持续持有两个源归档的稳定普通文件句柄，预检和解压只读取这些句柄，不复制整份源包。Windows `deny_writes` 阻止写入和删除，结束前复核路径与句柄身份，不再前后整包哈希；POSIX advisory lock 不能约束不配合的写入者，仍以流式 SHA-256 复核内容。文件夹和归档预捕获路径与实际打开句柄必须比较稳定文件 ID（Windows 卷序列号/FileId，其它平台设备号/inode），不能仅比较大小和 mtime。

源归档和文件夹快照默认不限大小、文件数；同一文件夹两端只稳定捕获一次，父子目录分别快照。文件夹仅复制实际变更端点，仍复核整个源树。归档按实际展开字节及保留正文/目录占位开销选择临时根。每个成员先验证临时根边界和 Windows 名称，拒绝穿越、绝对/盘符路径、ADS、符号链接、硬链接和设备等特殊成员；禁止无过滤 `extractall()`。合法字面 `ABC~1.TXT` 不因外形被拒绝，逐级核对真实目录项并排他创建，拒绝真实名称或短别名碰撞。文件夹与多版本快照同样拒绝 symlink/junction。

成员数、单成员大小、累计展开量、压缩比、TAR PAX/GNU 元数据记录/字段/字节及 ZIP 中央目录字节默认无性能型上限；显式策略仍生效，路径、类型、长度、CRC 和 I/O 失败仍严格检查。构造 `ZipFile` 前解析 EOCD/ZIP64 和中央目录，核对边界、计数并提前应用显式成员数策略。排除成员、重复副本及 sparse 映射的完整读取和计数规则见 [排除规则贯穿流程](#排除规则贯穿流程)，不得因减少落盘而跳过结构或正文校验。

`ArchiveVCS.set_exclude_patterns()` 必须同步内部 `FolderVCS`。`ignore_single_root=True` 时，两端各自必须恰有一个真实顶层目录且无其它项，只剥一层，不按排除结果筛选或猜测对应关系；桌面入口成对回退和严格 API 拒绝边界见 [覆盖与重新生成](#覆盖与重新生成)。内部比较根与权限元数据同时重定位，报告、排除、摘要、读取、导出、重命名和目录删除说明使用同一内层相对路径；所有权临时根不变。`comparison_note` 在单/多报告和上线说明展示两侧根名称，GUI `ignore_archive_root` 按新包路径及任务快照保存，旧配置默认关闭。

外部版本标签经 `_to_folder_ver()` 转为内部 old/new 侧再委托；内容、大小、摘要和流式导出使用同一映射。`main.py` 生成后将压缩包 `project_path` 改为包文件名，不能显示临时解压路径。

临时目录带所有权 sidecar，正常结束清理。创建新目录时仅回收超过七天、原进程已不存在且标记有效的专用遗留目录；Windows PID 探测复用 stage 所有权的保守句柄实现。标记必须为对象，创建时间为有限正数，PID 为正整数，布尔值不算有效数值；无效标记及目录原样保留，不阻断新任务。回归见 `tests/test_review_endpoint_labels_and_text.py`。

## 换行符处理

Windows 上 `core.autocrlf=true`（Git）或 `svn:eol-style=native`（SVN）会导致仓库存储 LF、工作副本为 CRLF。`git show` / `svn cat` 返回仓库原始字节（LF），若直接导出会与工作副本文件字节级不一致。

- **Git**：对固定 commit 批量查询属性，并复核 `core.autocrlf/core.eol`、filter 配置及系统/全局/info 属性文件摘要。`GitCheckoutSnapshot` 创建同对象格式的专用临时裸仓库，只读共享源对象，固定外部属性副本并隔离 Git 配置；使用 `GIT_ATTR_SOURCE` 与两个微小 blob 探针由原生 Git 判定属性的真实状态和换行模式。不能把 `cat-file --filters` 直接用于真实大文件；内容仍由 `git show` 流式落盘并分块转换，避免 Git 子进程为大文件创建完整转换副本。结束时清理普通/多版本的检出快照。
- 原生策略判定为自动 CRLF 时，按 Git `convert.c` 的完整字节统计处理：已有 CR/CRLF、NUL 或非文本控制字节密度过高时保留原文，不能只按“无 NUL”转换；显式强制文本则按原生结果处理含 NUL 文件。默认 EOL 仍是平台 native，`core.autocrlf` 优先级由原生 Git 决定。
- **SVN**：`SVNVCS._get_eol_style()` 对每个文件按所选 revision 执行 `svn propget svn:eol-style`，完整支持 `native` / `LF` / `CR` / `CRLF`。
- **文件夹**：直接从磁盘读取，不存在换行符差异
- **公共逻辑**：`BaseVCS._is_text_bytes()` 判断文本文件（不含 `\x00`），`BaseVCS._apply_crlf()` 用正则 `(?<!\r)\n` → `\r\n` 转换，避免重复转换已有的 CRLF

普通 Git/SVN 生成开始时必须把用户填写的可变版本标识固定为完整 commit OID/数字 revision，后续差异、内容、属性和导出均复用同一端点，报告仍显示用户原始输入。Git filter 名保留大小写，按驱动成组固定并复核 `smudge`、`process` 和 `required` 配置；没有检出程序且未要求强制转换的 filter（包括仅配置 clean）允许按普通文件导出。实际启用检出转换或要求强制转换的 filter，以及启用的 `working-tree-encoding`、`ident` 或旧 `crlf` 属性，仍因无法可靠复现 checkout 字节而拒绝该文件；桌面入口将其列为未完成，严格 API 中止。`check-attr` 输出中的 `set`/`unset`/`unspecified` 可能是同名字面 filter 驱动，必须由隔离 Git 区分；只复制“必需但无程序”的拒绝策略，不复制或执行 smudge/process，真正的 `-filter`/`!filter` 等状态仍可正常导出。普通 SVN 和 SVN 多版本均允许空值或仅含 ASCII 空白的 `svn:keywords`；`svn:externals` 的空白和整行注释不视为有效定义，其它定义及非空 keywords 仍须拒绝对应项目或文件；桌面入口记录未完成，严格 API 中止。

## 端点身份与展示标签

文件夹和多版本快照用 `EndpointSide` 明确区分新旧读取端点；报告保留用户输入的版本／目录标签。DiffEngine、FileExporter 和直接借用文件夹快照的包内报告使用相同侧别解析，不能把 Git 标签 `new`、`文件级首尾端点` 或相对目录 `old` 当成另一侧。旧 API 的字符串侧别别名保留兼容。显式借用交付 stage 的递归分析不再查询 VCS，也不重新解析展示标签。

## 批量读取与完整渲染补充（2026-09-24）

上文 Git 原始读取中的 `git show` 可由任务内持续运行的 `git cat-file --batch` 等价替代；兼容路径保留 `git show`。必须验证 blob 类型、声明字节数及协议结束符，导出仍分块写入，错误不得转成成功的空文件。原始对象通道不使用 `--filters`，检出属性和换行转换仍走既有独立规则；任务清理时关闭通道。

较大的替换段可以在调用 HtmlDiff 前选择现有 `stable_diff` 完整渲染，不必等到 RecursionError。算法选择阈值不构成规模限制，所有行、字符差异、精确行数统计、格式说明及所选上下文都必须保留。小修改继续使用原对齐方式；不得以优化为由截断报告或跳过输出范围检查。

## 文件夹扫描性能补充（2026-09-25）

Windows 文件夹比较允许合并同一时点的重复元数据查询，但不能降低路径安全边界。当前 Python 的 `lstat` 同时提供文件类型和 `st_reparse_tag` 时，应复用该结果；文件最终组件由 `OPEN_REPARSE_POINT` 安全打开并按句柄验证 reparse tag/FileId。

快照捕获与最终复核中，普通文件不必在目录遍历和紧随其后的安全身份打开各做一遍 leaf-link 查询；目录仍须在遍历进入前拒绝 junction/symlink。比较根的 `realpath` 可以在单个 `FolderVCS` 生命周期内缓存，但缓存键必须保留大小写，不能把大小写敏感目录中的 `old` / `OLD` 合并；每个目标路径仍须重新 `realpath` 并做根内判断，不能缓存目标解析结果。

以上均属于消除重复工作，不得移除读取前后句柄身份复核、源树最终复核、目录身份检查或异常时整次失败。回归见 `tests/test_folder_scan_optimization.py`。

2026-09-27 补充：Windows 接口结构和函数签名可以复用，但结果缓冲区必须逐次独立分配，
每次文件身份查询仍读取当前句柄。相对路径字符校验可以缓存不可变结果，缓存键保留原文、
校验策略和错误标签；缓存淘汰不能限制输入数量，公共可变返回值不能污染后续调用。
目录相对前缀可以在一次枚举中复用，进入目录前的链接检查、实际路径解析、读取前后身份检查
以及全源树最终复核均保留。对应回归为 `tests/test_folder_scan_followup.py`。

## 报告专用的压缩包递归

开启 `recursive_archives` 仅增加 `FileDiff.archive_details`。主 `files`、summary、manifest、old/new 导出和上线说明不得包含这些内部成员，不重新打包或修改交付字节。包内删除仅供审查，不能生成服务器删除命令。文件夹模式交付原包；压缩包模式仍按现有外层比较根交付变更成员，不继续拆开内层包。

递归支持 Git、SVN、folder、archive、Git多版本、SVN多版本及六模式混合多项目，默认关闭。安全解压、每报告共享计数、显式资源策略、过滤范围及错误行为见 [包内报告合同](nested-archive-report.md)。桌面入口逐包记录解析失败并保留原包，未知/未支持格式只标记未展开，不冒充已完成内部核验。

## 全模式包内报告的交付字节绑定（2026-09-26）

单项目递归启用时先完成 `prepare_export()`，分析器仅借用其返回的源码
stage；多项目先完成所有项目导出，再分析各项目子树。new/old 由显式侧别选取，
A 仅 new、D 仅 old、R 的 old 使用 old_path，其它两侧都必须存在。
原有 Git/SVN 检出规则及文件级端点不变，不能为了解析包回退到 raw 或工作副本。

有归档候选时在分析前通过 capture_stage_states 绑定源码 stage 内容；多项目
绑定两个外层 stage 根。发布前后比较 expected_stage_states，任何同大小同时间
戳内容变化或对象替换都必须使本次失败。不能先接受变化后的包再重新计算
“基线”。这里校验的是本次已分析的交付字节，无候选或关闭时不额外扫描。

来源提供者仅借用路径和普通文件句柄，不拥有 stage，不创建额外原包缓存，
不得删除 exporter 的暂存目录。桌面入口对包内解析失败保留原包，对模板失败生成基础报告；无法安全发布时清理本次暂存，明确报错且不恢复旧结果。完整验收见 [六模式递归验证](recursive-archives-all-vcs-verification.md)。

## 性能优化中的资源复用

glob 编译使用以规则及 `implicit_any_depth` 为键的有界纯函数缓存，允许规则直接赋值；缓存淘汰不是输入上限。浏览器详情保存模板引用，不预建所有 HTML 字符串；过滤和 manifest 基于完整数据，不能只看已挂载节点。

存在长重复游程时，行匹配按实际行数选择公共连续块，普通单行游程参与同一次
竞争；不得仅优先重复行或唯一行而打散更长公共正文。全文与上下文、字符串与
片段入口都要核对对齐质量，统计独立计算，不能以全文未丢代替高亮质量验收。

Git 微小 filters 探针通道仍按固定 endpoint 和完整隔离策略区分，最多保留两个
最近使用的通道，淘汰时先关闭再创建；已判定的 mode 独立缓存。资源预算不限制
版本数、文件数或结果，不能混用 GIT_ATTR_SOURCE、执行外部 filter 或改变失败协议。

任务内 SVN raw 缓存只发布完整成功的条目，身份包括固定仓库、历史 URL 和数字版本；
内容消费时在原本的完整读取中核对字节数、摘要和文件身份。失败、删除或替换不能命中
为成功空文件。只导出一次且没有缓存的二进制继续直接流式导出。
普通 SVN 现在拥有显式 cleanup；单/多项目成功与失败都必须调用，不能只依靠析构。
多版本先获取独立 raw，再按现有转换派生独立 export；不得转换 raw 本身或共享硬链接。

公共 DiffEngine 默认保留正文，内部工作线程可显式释放不再使用的正文；
导出继续读取固定原始/交付端点，不以显示正文代替真实字节。
应用内部显式传入 HtmlDetailStore 时，将完整 HTML 换成任务内片段引用；公共默认仍返回字符串。
一份报告共用一个私有追加文件，UTF-8 字节范围、完整性摘要与引用生命周期明确。
模板逐块读取；不得在 str/property/宏中偷偷重新加载完整片段。
包内 VCS 可先清理，片段由报告任务持有；报告写出完成后关闭。桌面入口对片段写入/读取失败记录展示问题或生成基础清单，继续交付已验证文件；严格 API 可中止。
stable 路径逐行产生片段，小修改的 HtmlDiff 和显式限制路径保持兼容。
这些措施减少 HTML 驻留，不取消原输入、行匹配或单条长行本身的内存需求。

归档不可变排除计划仅省去排除正文写盘，保持名称占位、完整读取校验、全量计数及显式资源策略。
公共可变排除规则仍全量解压；不能放宽规则后返回零字节占位冒充来源内容。
完整 TAR 预检与提取计划核对仍保留，旧 GNU sparse 格式继续使用兼容提取流程。
GNU/PAX 扩展目录的计划名称须与 tarfile 解析结果一致；原始扩展名称仍先接受路径校验，不能把绝对路径 `/` 规范化为空名后放行。名称规则及回归见 [TAR 目录名兼容](tar-directory-compatibility.md)。

旧输出的内容摘要与签名恢复机制已按新覆盖语义移除。已分析 stage 的内容绑定、源端点稳定性、路径隔离和并发互斥继续保留。
