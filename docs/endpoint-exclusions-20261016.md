## 行为与边界

- 普通 Git 取得原生变更关系后过滤；普通 SVN 区分真实文件/目录替换后按侧过滤。文件夹和归档保留提前筛选。
- Git/SVN 多版本的历史身份及分叉独立于业务排除，真实首尾端点规划完成后再逐侧过滤；中间经过排除目录不切断身份，排除分叉目标不改变原来的不确定性。项目范围边界仍先于历史身份竞争。
- SVN 分叉保留文件级因果关系，支持目标覆盖已有文件、多次未选分叉和后续路径变化；只有关系跨选中端点时才重新规划真实路径组，无关文件保留自身端点。普通复制不扩大选中源文件的端点。
- 冲突组中的目录只作为容器；文件与目录互换按完整路径分量关联后代依赖。旧文件路径被目录复用时保留新子文件，目录被文件覆盖时保留旧后代删除及必要目录操作，即使中间替换未被选中也不漏项。
- 最终旧侧排除为新增，新侧排除为删除，双侧排除跳过；被排除端点不生成正文快照。多版本快照生成后不允许修改规则，相同规则重复设置保持幂等。
- 文件和目录双向替换均检查排除依赖。若替换要求间接移除被排除的旧内容，相关变化整组标记未完成并退出报告主清单、导出及上线操作，独立文件继续；严格 API 拒绝该替换。
- 旧 GNU sparse TAR 的单块和连续扩展映射在物理正文前消费，验证范围、重叠和物理长度；逻辑长度进入展开预算，映射块受显式元数据策略约束。格式、路径和排除正文完整性检查继续保留。
