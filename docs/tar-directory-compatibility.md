## 名称与安全边界

GNU 长名称记录和 PAX `path` 可以携带目录末尾 `/`。预检先前保留扩展名称，而实际提取使用的 Python 3.12 `tarfile` 会处理末尾斜杠；同一个目录因字符串不同被误报为“成员与完整预检不一致”。

预检分别保存原始名称 `name` 和有序提取计划名称 `plan_name`：

- 原始扩展名称继续交给路径边界及 Windows 名称校验；绝对路径、盘符、父目录穿越、ADS 和碰撞仍拒绝，排除规则不能隐藏这些输入。
- GNU 扩展目录名的计划名称去除一个末尾 `/`；PAX 扩展目录名去除全部末尾 `/`，与当前标准库一致。普通头由 `TarInfo.frombuf()` 解析后的名称保持不变，普通文件不套用目录规则。
- 实际提取仍逐项核对计划名称、类型、长度和权限，任何真实差异都中止，不捕获忽略错误、不跳过成员。旧 GNU sparse 沿用原兼容路径。

特别是扩展目录名 `/`：不能因计划名称变为空字符串而被当成合法归档根。新增回归同时覆盖 GNU 长名称记录和 PAX `path`，确认原始绝对路径仍被拒绝。
