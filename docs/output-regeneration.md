# 覆盖重建与日志保留：实现和验证

日期：2026-09-27。源码基线：`35711cf03b9b2d756937011ed77c79098b5f0888`，本记录描述该基线之后的覆盖重建与日志保留改造。记录范围为源码验收，不代表用户正在使用的 EXE 已更新。

## 已确认的产品规则

用户明确接受报告和导出可以重复生成，确认覆盖即允许丢弃上次结果，生成失败也不需要恢复。因此退役原有旧输出备份、事务日志、HMAC 私钥和签名恢复、提交/回滚标记、跨阶段旧内容摘要校验。

当前流程：

1. 校验输入与输出隔离、明确的输出目标、路径边界、实际 Windows 名称及目标类型。
2. 取得输出批次锁；同批次已有任务时，在删除前报忙。
3. 删除本次项目的旧报告、上线说明及 `oldVersion/项目名`、`newVersion/项目名`。不读取旧文件正文，不清空整个输出根。
4. 执行比对，把新的报告、说明和导出写入私有暂存项。
5. 全部生成成功后发布新结果，报告最后发布；清理完成后释放锁并通知界面。

删除失败时停止生成；此前已经删除的部分不恢复。生成或发布失败时清理本次暂存及仍能确认属于本次的部分新结果，不恢复旧结果。强制结束进程可能留下本次暂存或部分输出，没有跨进程恢复承诺；重新生成即可重新建立正式结果。

其他项目、输出根下的无关文件和多项目历史运行目录保持原样。多项目继续使用独立 `multi_run_...` 目录，全部项目成功才发布本次结果。生成期间外部程序重新创建的正式目标不能被自动覆盖，发布失败并保留它。

历史版本留下的恢复记录和备份不参与启动或生成，不校验其签名，也不按记录中的路径删除文件。此次没有清理用户已有的历史备份。

## 保留的检查与简化范围

- 保留源端点固定、真实检出字节、路径和链接检查，避免误删源码、越界读取或错误交付。
- 保留同一输出批次的互斥，防止两个实例同时删除和写入同一批输出。
- 开启包内递归且存在候选包时，保留本次暂存包与报告的内容绑定；发布前后仍核对其内容。关闭递归或没有候选时不增加该扫描。
- 原 `_tree_identity()` 只用于上述本次交付内容绑定，不再扫描旧输出。任务阶段 `output.clear` 表示删除旧结果，`output.commit` 表示发布本次完整结果；旧阶段名称保留不代表还有旧事务机制。

源码入口为 `main.py` 的单/多项目工作线程及 `file_exporter.py` 的 `output_session()`、`_replace_outputs()`。详细约束以 [完整性合同](report-and-export-contract.md#覆盖与重新生成) 为准。

## 日志不会随历史任务无限积累

| 日志 | 保留规则 |
| --- | --- |
| `compareTool.log` | 最多 512 KiB，写入前判断是否轮转 |
| `compareTool.log.bak` | 仅一份，最多 512 KiB；兼容裁剪旧版本留下的超大日志 |
| 单条普通日志 | 最多 64 KiB，超长内容附截断说明，保持 UTF-8 可读 |
| `logs/tasks/task_*.jsonl` | 过程事件最多 512 KiB，结束事件另最多 64 KiB |
| 对应 `.json` 摘要 | 最多 64 KiB；摘要过大时保留基本诊断字段并标记 `details_truncated` |
| 任务历史数量 | 成功、失败、中断和不完整记录合计最近 50 组，在任务开始与结束时清理 |

程序按上述规则新写出的普通日志和备份合计最多 1 MiB，50 组任务历史合计最多约 31.25 MiB。正在运行的任务不被历史清理删除，每份日志仍受大小约束。无法归属于本程序的文件不自动清理；历史外来文件或旧版异常超大任务记录不属于这个新写入体积估算。

限制只作用于诊断日志，不截断报告、变更清单或导出文件。日志不可写仍不影响业务结果。文件数量测试覆盖成功、失败、中断、半条 JSON、当前进程及其他存活进程的日志，避免只清理成功任务而让中断记录持续增长。
