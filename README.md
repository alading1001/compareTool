# 代码比对报告工具

Windows 桌面应用，输入 Git/SVN/文件夹/压缩包 项目路径和版本信息，一键生成 HTML 差异报告并导出变更文件。通过 PyInstaller 打包成单文件 exe，无需 Python 环境。

## 功能

- 支持 **Git**、**SVN**、**文件夹对比**、**压缩包比对**、**Git需求包**和**SVN需求包**六种模式
- Git/SVN 模式一键获取最近 100 条版本列表（含提交注释），双击填入
- Git需求包/SVN需求包支持多选需求相关版本，按「基线 + 选中版本」生成需求包差异报告
- 支持多项目批量任务，一次生成跨项目/微服务的总报告并按项目名导出变更文件
- 支持输出批次名称，在基础输出目录下按系统/版本/上线批次再分一层目录
- 压缩包模式支持 `.zip` / `.jar` / `.war` / `.ear` / `.aar` / `.tar` / `.tar.gz` / `.tgz` / `.tar.bz2` / `.tbz2`，自动处理中文文件名编码
- 输入新旧版本号，自动生成**左右分栏对比**的 HTML 报告
- 左侧文件树，按颜色标记：🟢 新增 / 🔵 修改 / 🔴 删除 / 🟣 重命名
- 文件树支持「全部 / 新增 / 修改 / 删除 / 重命名」过滤标签，可任意组合
- 支持目录折叠展开，一键全部展开/折叠
- 点击文件查看代码差异（新增/修改/删除行高亮，行号着色）
- **纯文本变更清单**，按新增/修改/删除/重命名分类列出所有变更文件
- 差异展示方式可选：**全部内容** 或 **仅差异上下文**（前后各 3 行）
- 自动导出新版本和旧版本的变更文件，空文件正常导出
- 导出文件自动匹配 Windows 换行符（Git autocrlf / SVN eol-style），与工作副本字节一致
- 支持 **glob 排除规则**（`*.class`、`target/**` 等），避免编译产物干扰
- 二进制/归档文件（`.jar`、`.war`、`.class` 等）标记变更但不展示内容
- SVN 可执行文件路径自动探测（PATH → 注册表 → 常见安装目录），亦可手动指定
- 中文编码自动适配（子进程输出 + 文件内容均 UTF-8 → GBK 回退）
- 配置自动记忆，下次打开恢复上次设置

## 运行

### 开发环境

```bash
pip install jinja2
python main.py
```

### 打包为 exe

```bash
build.bat
```

打包后的 exe 在 `dist/CompareTool.exe`。使用 `--console` 模式打包，确保 git/svn 子进程有终端可用。应用图标使用 `assets/icons/app.ico`，打包时会同时写入 exe 图标和运行时窗口图标。

## 使用说明

1. 选择项目目录，选择版本控制类型（Git / SVN / 文件夹 / 压缩包 / Git需求包 / SVN需求包）
2. Git/SVN 模式点击「获取版本列表」查看可用版本（含提交注释，单击选中后点「←填入」或双击直接填入）
3. Git需求包/SVN需求包模式点击「获取版本列表」后可 `Ctrl/Shift` 多选需求版本，也可手工用逗号、分号或换行输入多个版本号
4. 确认项目名，工具会从有效项目目录/新版本文件夹/新版本压缩包自动推断；推断不到时需手动填写
5. 输入/修改排除规则（支持 `*` 和 `**` 通配符）
6. 设置输出目录，可选填写输出批次名称，点击「生成比对报告」
7. 生成完毕后自动询问是否打开报告

**多项目总报告**：配置好当前项目后，填写/确认「项目名」，点击「添加到多项目任务」。任务列表支持编辑、删除、清空和持久化保存。任务会保存排除规则、是否使用项目名、差异展示方式等设置快照。点击「生成多项目总报告」后，工具会按任务顺序处理所有项目，生成 `multi_compare_report_yyyyMMdd_HHmmss_SSS.html`，并导出：

```
oldVersion/项目名/...
newVersion/项目名/...
```

多项目任务允许混用 Git、SVN、文件夹、压缩包、Git需求包和 SVN需求包。任一任务失败时，本次总报告生成失败，不跳过项目。总报告的变更清单按新增/修改/删除/重命名汇总，不按项目分组；每条路径是否带项目名由所属任务自己的「报告树及变更清单使用项目名」决定。若多个项目最终展示路径完全相同，工具会停止生成并提示用户开启相关任务的项目名展示，避免文件树和清单出现歧义。

**输出批次名称**：在「输出目录」下额外增加一层子目录，便于按系统版本或上线批次归档。每次启动默认当天日期（如 `20260530`），不写入配置文件，用户可手工修改或清空。例如输出目录为 `C:/Users/12939/Desktop/444`，输出批次名称为 `订单系统_v1.0.1`，则报告和 `oldVersion` / `newVersion` 都会生成到 `C:/Users/12939/Desktop/444/订单系统_v1.0.1/` 下。留空时保持旧逻辑，直接输出到选择的输出目录。生成前会提示当前批次名称和实际输出目录，需确认后继续。

**文件夹对比模式**：选择两个文件夹分别作为旧版本和新版本，直接比对文件差异（基于 `filecmp.cmp` 内容比较），无需 VCS。

**压缩包比对模式**：选择两个压缩包作为旧版本和新版本，工具自动解压到临时目录后比对。支持 `.zip`、`.jar`、`.war`、`.ear`、`.aar`、`.tar`、`.tar.gz`、`.tgz`、`.tar.bz2`、`.tbz2` 格式。

**Git需求包 / SVN需求包模式**：用于按需求拆分上线包。选择多个需求相关提交/修订后，工具会自动取最早选中版本的前一个版本作为基线：

```
old = 最早选中版本的前一个版本
new = old + 按时间顺序应用所有选中版本
报告 = old 与 new 的差异
```

例如提交顺序为 `C提交 → A需求1 → B需求1 → A需求2 → B需求2`，只选择 `A需求1` 和 `A需求2` 时，报告体现的就是 A 需求本次改动。若选中的版本依赖未选中的版本，临时应用提交/修订时可能冲突，工具会停止生成并提示冲突文件。

需求包模式只在系统临时目录中创建工作副本，成功或失败后都会自动清理，不会修改真实项目目录。Git需求包会列出当前分支主线最近 100 条提交，并用 `[merge]` 标记合并提交；普通提交直接应用，合并提交按第一父提交（mainline）计算合入主线后的净变化。SVN需求包只列出当前项目 URL 相关的最近 100 条 revision，不查询全仓库提交。

**重命名处理**：Git/SVN 明确返回的重命名会按 `旧路径 -> 新路径` 展示；文件夹、压缩包、Git需求包、SVN需求包等快照类比对中，若一个删除文件和一个新增文件内容字节完全一致且唯一匹配，也会自动合并为重命名。若重命名同时修改内容且无法明确判断，则保持删除 + 新增。导出时 oldVersion 使用旧路径，newVersion 使用新路径。

## 排除规则

工具内置一套通用默认排除规则，每行一个 glob 模式。新项目没有专属配置时使用这套默认模板；在界面里修改后，会按项目目录（压缩包按新版本压缩包完整路径）单独记忆。

```
*.class
**/target/**
**/.git/**
**/.idea/**
**/node_modules/**
**/__pycache__/**
...
```

规则语法：
- `*.class` — 匹配任意深度的 .class 文件
- `target/**` — 匹配 target 目录下所有文件
- `**/test/**` — 匹配任意位置的 test 目录

## 配置文件

`compareTool_config.json` 自动保存上次的项目路径、VCS 类型、SVN 路径、输出路径、多项目任务列表，以及按项目路径记忆的排除规则和显示选项。输出批次名称不持久化，每次启动默认当天日期。新项目没有专属规则时，直接使用代码内置默认模板；旧版全局 `exclude_rules` 不再作为默认模板来源。
