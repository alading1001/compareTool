# 代码比对报告工具

Windows 桌面应用，输入 Git/SVN/文件夹/压缩包 项目路径和版本信息，一键生成 HTML 差异报告并导出变更文件。通过 PyInstaller 打包成单文件 exe，无需 Python 环境。

## 功能

- 支持 **Git**、**SVN**、**文件夹对比**、**压缩包比对**、**Git多版本**和**SVN多版本**六种模式
- Git/SVN/Git多版本/SVN多版本模式的项目名支持最近项目下拉，按 Git/SVN 家族记忆最近 10 个项目
- Git/SVN 模式一键获取最近 100 条版本列表（含提交注释），支持关键词搜索、双击填入和显示/隐藏列表
- Git多版本/SVN多版本支持多选需求相关版本，按每个文件自己的首次/末次选中变更生成首尾净差异
- 支持多项目批量任务，一次生成跨项目/微服务的总报告并按项目名导出变更文件
- 支持输出批次名称，在基础输出目录下按系统/版本/上线批次再分一层目录
- 压缩包模式按内容识别 ZIP、TAR、GZIP 和 gzip/bzip2 压缩 TAR，支持 `.dat.gz` 等单文件压缩及改后缀或无后缀的真实归档，自动处理 ZIP 中文文件名编码
- 压缩包可勾选「忽略最外层单一文件夹」，按两包内层内容比较；默认不勾选，保留完整目录结构
- 输入新旧版本号，自动生成**左右分栏对比**的 HTML 报告
- 左侧文件树，按颜色标记：🟢 新增 / 🔵 修改 / 🟠 格式变化 / 🔴 删除 / 🟣 重命名
- 文件树只显示本次报告实际存在的「新增 / 修改 / 格式变化 / 删除 / 重命名」过滤标签，并保留「全部」，可任意组合
- 普通文件和包内文本成员均可在鼠标点击「上一处 / 下一处」后，用左右方向键横向查看当前正文；键盘激活按钮时仍保留按钮焦点
- 支持目录折叠展开，一键全部展开/折叠
- 点击文件查看代码差异（新增/修改/删除行高亮，行号着色）
- **纯文本变更清单**，按新增/修改/格式变化/删除/重命名分类列出所有变更文件
- 差异展示方式可选：**全部内容** 或 **仅差异上下文**（前后各 3 行）
- 大段相似文本触发标准差异引擎递归异常时，自动继续生成完整逐行对比。编码未识别的字节显示为带底色的 `⟦0xXX⟧`，保留真实差异和原始导出字节。
- 桌面六模式默认尽量导出：独立文件或项目失败会列出未完成项，其余继续；重命名身份不确定时按真实路径降级为删除/新增/修改。实际 Windows 名称碰撞的双方均退出交付，独立合法的 `~` 文件名仍可使用。
- 自动导出新旧变更文件与上线说明。确认覆盖后先删除本次项目旧结果，再重新生成；失败不恢复旧结果。其他项目和无关文件保留，新结果完整生成后才发布。历史恢复记录与备份不再参与生成，不会因签名错误阻断新任务。每次多项目生成使用独立运行目录。
- 导出文件按 Git `.gitattributes` + `core.autocrlf/core.eol` 或 SVN `svn:eol-style` 匹配所选版本应有的换行符
- 支持 **glob 排除规则**（`*.class`、`target/**` 等），避免编译产物干扰
- 二进制/归档文件默认只标记变更；启用包内递归后，受支持归档可逐层查看文本成员，`.class` 等二进制成员仍不展示正文
- Git/SVN 可执行文件路径自动探测（PATH → 注册表 → 常见安装目录），找不到时提示安装命令行工具
- 中文编码自动适配（子进程输出 + 文件内容均 UTF-8 → GBK 回退）
- 配置自动记忆；文件夹、压缩包分别恢复上次的新旧路径，切换模式和正常退出后重启均可继续使用

## 运行

### 开发环境

```bash
pip install jinja2
python main.py
```

### 打包为 exe

```bash
build.bat
```

`build.bat` 会优先复用项目内 `.venv`；不存在时优先使用本机 Python 3.12 创建 `.venv`，并按 `requirements.txt` 补齐构建依赖。打包后的 exe 在 `dist/CompareTool.exe`。使用 `--console` 模式打包，确保 git/svn 子进程有终端可用。应用图标使用 `assets/icons/app.ico`，打包时会同时写入 exe 图标和运行时窗口图标。

## 使用说明

完整操作手册见 [CompareTool 使用说明书（PDF）](docs/CompareTool_使用说明书.pdf)，涵盖六种比较模式、报告阅读、导出目录及常见问题。源稿和维护步骤见 [说明书维护](docs/manual/README.md)。`build.bat` 打包时会把正式 PDF 复制到 `dist`，与 EXE 一起分发。

1. 选择项目目录，选择版本控制类型（Git / SVN / 文件夹 / 压缩包 / Git多版本 / SVN多版本）
2. Git/SVN 模式点击「获取版本列表」查看可用版本（含提交注释，支持在当前列表内搜索；单击选中后点「←填入」或双击直接填入）
3. Git多版本/SVN多版本模式点击「获取版本列表」后可 `Ctrl/Shift` 多选版本，也可手工用逗号、分号或换行输入多个版本号；搜索过滤和隐藏列表不会清空已选版本
4. 确认项目名，工具会从有效项目目录/新版本文件夹/新版本压缩包自动推断；Git/SVN/Git多版本/SVN多版本可从项目名下拉中选择最近项目并同步回填项目目录；推断不到时需手动填写
5. 输入/修改排除规则（支持 `*` 和 `**` 通配符）
6. 设置输出目录，可选填写输出批次名称，点击「生成比对报告」
7. 生成完毕后自动询问是否打开报告

**版本列表操作**：Git/SVN/Git多版本/SVN多版本获取版本列表后，搜索框只过滤当前已经展示的最近版本，不会额外查询仓库。点击「隐藏版本列表」会收起列表区域，便于查看下方多项目任务；按钮会切换为「显示版本列表」，再次点击可恢复列表。隐藏列表不会清空版本缓存、搜索条件或多版本选择状态；重新获取版本列表时会自动展开。

**多项目总报告**：配置好当前项目后，填写/确认「项目名」，点击「添加到多项目任务」。任务列表支持编辑、删除、清空和持久化保存。任务会保存排除规则、是否使用项目名、差异展示方式等设置快照。编辑旧任务仍保留已有快照；更换来源目录或新版本压缩包后才切换项目默认设置。点击「生成多项目总报告」后，工具会按任务顺序处理所有项目，并在批次根下创建独立的 `multi_run_yyyyMMdd_HHmmss_SSS_<8位随机十六进制>/` 运行目录。该次报告、上线说明和源码包都保存在此目录：

```
multi_run_.../multi_compare_report_yyyyMMdd_HHmmss_SSS.html
multi_run_.../上线操作说明.txt
multi_run_.../oldVersion/项目名/...
multi_run_.../newVersion/项目名/...
```

多项目任务允许混用 Git、SVN、文件夹、压缩包、Git多版本和 SVN多版本。独立项目读取失败时保留诊断记录，后面的项目继续，报告与完成提示明确标注部分交付。总报告的变更清单按新增/修改/格式变化/删除/重命名汇总，不按项目分组；每条路径是否带项目名由所属任务自己的「报告树及变更清单使用项目名」决定。多个项目展示路径相同时，自动为相关项目补充项目前缀并注明，不修改保存的任务偏好。

**输出批次名称**：在「输出目录」下额外增加一层子目录，便于按系统版本或上线批次归档。每次启动默认当天日期（如 `20260530`），不写入配置文件，用户可手工修改或清空。例如输出目录为 `C:/Users/12939/Desktop/444`，输出批次名称为 `订单系统_v1.0.1`，则单项目产物直接生成到 `C:/Users/12939/Desktop/444/订单系统_v1.0.1/`；多项目产物再进入该批次根下独立的 `multi_run_.../`。留空时以选择的输出目录作为批次根。生成前会提示本次真正写入的批次根或 multi run 目录，需确认后继续。

**文件夹对比模式**：选择两个文件夹分别作为旧版本和新版本。生成开始时捕获两端文件身份，用分块字节读取判断差异，只把实际变更端点快照到 CompareTool 专用临时目录，最后复核整个源树；无需 VCS，源目录在此期间变化时会明确失败，避免混入后续内容。

**压缩包比对模式**：选择两个压缩包作为旧版本和新版本，工具按内容识别 ZIP、TAR、GZIP 和 gzip/bzip2 压缩 TAR，自动解压到专用临时目录后比对。选择框默认显示“所有文件”，改后缀或无后缀的真实包也能直接选择；可按需切换到“常见压缩文件”筛选。普通文本改名为 `.tar.gz` 仍会拒绝作为外层包。单文件 GZIP（如 ODS `.dat.gz`）解压后直接比较数据正文；成员名取外部文件名去掉 `.gz`，无 `.gz` 时追加 `.unpacked`，不采用 GZIP 头部的 FNAME。RAR、7z、XZ 可识别但暂不展开。解压会拒绝 `../`、绝对/盘符路径、Windows 非法路径及 ADS、符号链接、硬链接和特殊文件。成员数、单成员大小、累计展开量、压缩比及递归层数默认不限，显式注入的资源策略仍有效；长度、CRC、来源身份和实际 I/O 必须通过校验。

**压缩包外层目录**：如果两包都只有一个顶层文件夹，可勾选「忽略最外层单一文件夹」。例如旧包 `release_old/config/app.xml` 和新包 `release_new/config/app.xml` 会按 `config/app.xml` 比较。仅忽略一层，报告、排除规则和导出使用相同的内层相对路径；报告与上线说明会标明两侧实际比较根目录。任一包结构不满足时，桌面入口将两侧一起退回完整包路径并注明；严格 API 仍拒绝。此设置按新压缩包路径记忆，并保存到每个多项目任务；旧配置默认不勾选。比较发布包时也要检查默认排除规则，避免漏掉需要比较的 WAR、class 等内容。

**包内同名文件**：名称完全相同、内容及相关文件属性一致的重复成员可以正常比较，报告会注明重复项。每份都完整校验，但只保留一份比较内容；内容或属性冲突仍会报错。递归报告不会修改交付的原始压缩包。边界及验证见 [重复归档成员兼容](docs/archive-duplicate-members.md)。

**TAR 长目录**：GNU/PAX 扩展目录名可正常比较。旧版若报“成员与完整预检不一致”，且目录名仅末尾 `/` 不同，需使用包含 2026-10-09 修复的新构建。原因和验证范围见 [TAR 目录名兼容](docs/tar-directory-compatibility.md)。

**Git 项目范围**：普通和多版本模式都支持选择仓库内子项目。报告、排除规则和源码包均以所选目录为根，兄弟项目的文件不会混入；跨边界移动按本项目一侧的新增或删除处理。裸仓库仍可导出到仓库之外。

**Git多版本 / SVN多版本模式**：用于从多个需求相关提交或修订中生成文件级首尾净差异。选中版本决定候选文件集合；每个文件分别取“首次选中变更之前”的真实状态作为 old，取“末次选中变更之后”的真实状态作为 new。工具不读取更晚的工作副本/HEAD，不为所有文件套用统一最高版本，也不通过 cherry-pick 或 SVN merge 合成文件。

例如选中 `r3`（修改 `B.java`）和 `r6`（修改 `A.java`）：

```text
B.java：old = B@r2，new = B@r3
A.java：old = A 在 r6 前的真实状态，new = A@r6
```

同一文件跨多个选中版本时，比较首次选中前与末次选中后的最终净结果；中间未选中的修改不单独展示，但会自然体现在末次选中版本的真实文件状态中。新增后又删除、修改后又恢复等最终完全抵消的文件不进入报告和导出。完整语义与场景见 [`docs/multi-version-file-endpoints.md`](docs/multi-version-file-endpoints.md)。

Git多版本只接受当前分支第一父历史中的提交，合并提交相对第一父提交计算净变化；浅克隆缺少父对象时中止。Git 先用可靠阈值追踪重命名并保存紧凑竞争结构；只有不同逻辑实体确实跨越选中端点时，才运行低阈值第二遍差异或隔离 blob 相似度评分，跨提交候选也会先按活动区间、目标事件和最终端点过滤。身份跨越选中端点却无法唯一确认时，按冲突连通组的真实路径首尾状态降级为删除/新增/修改，并在报告注明；无关中间文件的低相似重命名或类型变化不会阻断。SVN多版本沿当前项目 URL 的 revision 历史追踪文件及目录移动，通过 `copyfrom-path`、历史项目前缀和删除覆盖关系保留文件身份；项目根/祖先/嵌套目录移动、子文件移出目录或覆盖目标、移动后删除源祖先均按真实文件身份处理，普通 copy 和同源多目标不会被强猜成唯一 rename。

归档解压和多版本模式共用 CompareTool 专用临时目录，成功或失败后都会自动清理，不会修改真实项目目录。可通过环境变量 `COMPARETOOL_TEMP_DIR` 显式指定位置；未指定时，源码/exe 位于非系统盘则优先使用其同盘 `.tmp/comparetool_runtime`，Windows 下源码/exe 位于 C 盘且 D 盘可用时优先使用 `D:\applications\_cache\CompareTool\tmp`，只有前述位置都不可用时才回退到系统临时目录。Git多版本列出当前分支第一父历史最近 100 条提交，并用 `[merge]` 标记合并提交；SVN多版本只列出当前项目 URL 相关的最近 100 条 revision，不查询全仓库提交。

大文件导出、多版本端点快照和 Git 重命名候选评分均采用流式处理，不把完整二进制载入内存；Git/SVN 的可变版本、检出配置与仓库身份会在任务开始时固定。正常生成默认不设命令超时，也不按历史记录数、路径字节、逻辑文件数、端点文件数、文本大小、行数、最长行、报告明细数或最终 HTML 大小提前拒绝、跳过或截断；目录覆盖和 SVN 多版本目录移动使用前缀索引/路径层级查询，不枚举无意义的文件×目录笛卡尔积。Git 多版本的 1% 第二遍 diff、隔离 blob 评分和跨提交候选组合会先按最终文件端点与时序过滤，只有结果可能影响身份判定时才执行，命中歧义后收集相关冲突组并降级。报告用 Jinja2 流式写入同目录临时文件并原子替换，变更清单完整；详情完整时清单直接复用文件数据，不重复序列化同一批路径。同一文件夹作为两端时只捕获一次并正常生成零变更结果；其它文件夹端点会固定完整树身份，只把实际变更端点复制到临时目录。压缩包持续持有源句柄并按真实展开量选择有空间的临时根，不额外复制整份源归档；Windows 由 deny-writes 句柄锁定内容，不再前后重复整包哈希，POSIX 仍做摘要复核。仍保留会影响正确源码的失败边界，例如源端点变化、读取不完整、不可复现的 Git filter/SVN keywords 或特殊节点。桌面入口记录受影响文件或项目未完成，其余继续；输出边界、暂存字节和发布失败仍会中止。Git 属性和 EOL 配置由隔离的原生 Git 在固定端点上判定，实际大文件仍流式导出：自动模式会保留已有混合换行、孤立 CR 和二进制内容，显式文本按 Git 的强制转换规则处理。默认 EOL 为平台 native。每次多项目输出目录使用“毫秒时间戳 + 随机标识”，并发生成不会互相覆盖。

没有检出转换程序且未要求强制转换的 Git filter（包括仅配置 clean），以及空值或仅空白的 SVN keywords，均可正常导出，普通与多版本模式保持一致。Git filter 驱动名即使叫 `set`、`unset` 或 `unspecified`，也不会被误当成禁用状态；真正的 `-filter`/`!filter` 仍正常导出。有效的外部检出程序不会被执行，无法可靠复现时明确失败。SVN externals 为空、空白或仅有整行注释时允许导出；根目录或未完整排除子目录有实际定义时，项目会标为未完成，即使该属性本次没有变化，也不能宣称完整交付。报告仅按 CR/LF 拆行；换页符、Unicode 分隔符等会参与差异计算，并显示为 `⟦U+XXXX⟧`，导出的文件保留原始字符。

**上线操作说明**：每次生成都会在报告、`oldVersion`、`newVersion` 同级生成带 UTF-8 BOM 的说明文件；单项目名为 `<项目名>_上线操作说明.txt`，多项目名为 `上线操作说明.txt`。文件列出需要从目标环境删除的旧路径和重命名对应关系；多项目路径始终带项目名，不受报告展示选项影响。即使本次没有删除或重命名也会生成并明确写“无”，防止交付方误判漏文件。确认覆盖会先删除本次项目的四类旧输出，失败不恢复。新内容写在可信输出根的暂存项中，全部完成后发布，报告最后安装；批次锁防止同时生成，路径检查防止误删输入或其他项目。完整约束见 [覆盖与重新生成](docs/report-and-export-contract.md#覆盖与重新生成)。

**重命名处理**：普通 Git/SVN、文件夹和压缩包模式保持原有重命名识别；Git多版本/SVN多版本由历史端点规划器追踪文件身份，不再对最终删除/新增按内容二次猜测。重命名同时发生编码/BOM/换行变化时会明确显示格式说明；跨越排除边界时改为新增或删除。导出时 oldVersion 使用旧路径，newVersion 使用新路径，并把旧路径写入 `上线操作说明.txt`。普通 Git 比对遇到文件类型变化会拒绝该路径并记录未完成；Git 多版本历史中的类型变化只延续同路径身份，最终选中端点为非普通 mode、`svn:special` 或其它非普通文件时拒绝该文件；桌面入口继续其他独立文件，严格 API 仍中止。格式净差异另用仓库原始字节判断，防止换行转换把真实格式变化过滤掉。

## 排除规则

工具内置一套通用默认排除规则，每行一个 glob 模式。新项目没有专属配置时使用这套默认模板；在界面里修改后，会按项目目录（压缩包按新版本压缩包完整路径）单独记忆。

恢复多项目任务时，排除规则为 null、数组或其它非字符串的损坏记录会告警并跳过，不能静默关闭过滤。旧记录缺少该字段时告警并采用默认模板；用户明确保存的空字符串仍表示不排除。恢复结果会在下次正常保存配置时持久化。

Git/SVN 多版本先追踪完整项目历史，确定文件首尾端点后再按新旧两侧排除。中间经过排除目录不会切断身份；排除复制分叉中的某个目标也不会把分叉改判为唯一重命名。旧侧排除显示新增，新侧排除显示删除，双侧排除跳过。文件夹和压缩包仍可提前剪枝或省去排除正文写盘。目录替换若会连带删除被排除的旧内容，相关变化会标记未完成。报告、源码包和上线说明共同使用实际成功交付集合。

本轮源码改造和完整回归见 [最终端点排除与 GNU sparse TAR 验收](docs/endpoint-exclusions-20261016.md)；相关修复已随 `2026.10.16.2` 重新打包并通过真实窗口及业务冒烟。

## 配置文件

`compareTool_config.json` 自动保存上次的项目路径、VCS 类型、输出路径、多项目任务列表、最近项目列表，以及按项目路径记忆的排除规则和显示选项。写入失败会明确报错，不再显示假成功；启动时会忽略 schema 损坏或 VCS 类型未知的多项目任务，避免整个窗口无法打开。最近项目按 Git/SVN 家族分组，每组最多保留最近 10 个有效项目。输出批次名称不持久化，每次启动默认当天日期。新项目没有专属规则时，直接使用代码内置默认模板；旧版全局 `exclude_rules` 不再作为默认模板来源。

## 架构与版本标识

1. `main.py` 收集输入：项目路径、VCS 类型（Git/SVN/文件夹/压缩包/Git多版本/SVN多版本）、旧/新版本号或多版本列表、排除规则、输出目录
2. 根据 VCS 类型创建 `GitVCS` / `SVNVCS` / `FolderVCS` / `ArchiveVCS` / `GitMultiVersionVCS` / `SVNMultiVersionVCS` → `get_changed_files()` 获取变更文件列表
3. `DiffEngine.generate_diff()` 遍历文件，对文本文件生成 side-by-side HTML（标准 `HtmlDiff` 及完整非递归回退）；二进制文件跳过内容只设占位标记；普通模式下内容完全一致且唯一匹配的删除+新增可合并为重命名，多版本保留端点规划器的身份结果
4. `FileExporter` 先将可验证的新旧端点导出到暂存目录，过滤未完成项；包内递归借用实际交付的暂存端点
5. `ReportGenerator` 渲染单文件 HTML（模板失败时生成基础清单），与上线说明及导出文件一起校验发布；详细约束见 [完整性合同](docs/report-and-export-contract.md)

| SVN | `rNNNNN` 或 `NNNNN` | 同左 | `get_file_content` 使用仓库 URL + peg revision |
| 文件夹 | 旧文件夹路径 | 新文件夹路径 | 固定树身份，只快照变更端点并复核源树；兼容 `"old"`/`"new"` 和用户输入的实际路径 |
| 压缩包 | 旧压缩包路径 | 新压缩包路径 | 按内容识别 ZIP、TAR、GZIP 和 gzip/bzip2 压缩 TAR，解压到临时目录后委托 `FolderVCS` 比对 |
| Git多版本 | 多个 commit hash | `文件级首尾端点` | 每个文件 old 取首次选中变更的第一父提交，new 取末次选中提交 |
| SVN多版本 | 多个 `rNNNNN` 或 `NNNNN` | `文件级首尾端点` | 每个文件 old 取首次选中 revision 前状态，new 取末次选中 revision 后状态 |

### 编码

- **SVN 子进程输出**：`_run()` 读取原始字节，通过 `_decode_bytes()` 自动探测编码（UTF-8 → GBK → 回退）。影响 svn log、svn diff、svn info 等所有命令输出
- **SVN cat / 本地文件**：同样走 `_decode_bytes()`（UTF-8 → GBK）
- **Git 路径**：`_unescape_git_path()` 解码 `core.quotepath` 的八进制和 C 风格转义（包括 tab、换行、引号和反斜杠）。
