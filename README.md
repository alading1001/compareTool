# 代码比对报告工具

Windows 桌面应用，输入 Git/SVN/文件夹/压缩包 项目路径和版本信息，一键生成 HTML 差异报告并导出变更文件。通过 PyInstaller 打包成单文件 exe，无需 Python 环境。

## 功能

- 支持 **Git**、**SVN**、**文件夹对比**、**压缩包比对**、**Git多版本**和**SVN多版本**六种模式
- Git/SVN/Git多版本/SVN多版本模式的项目名支持最近项目下拉，按 Git/SVN 家族记忆最近 10 个项目
- Git/SVN 模式一键获取最近 100 条版本列表（含提交注释），支持关键词搜索、双击填入和显示/隐藏列表
- Git多版本/SVN多版本支持多选需求相关版本，按每个文件自己的首次/末次选中变更生成首尾净差异
- 支持多项目批量任务，一次生成跨项目/微服务的总报告并按项目名导出变更文件
- 支持输出批次名称，在基础输出目录下按系统/版本/上线批次再分一层目录
- 压缩包模式支持 `.zip` / `.jar` / `.war` / `.ear` / `.aar` / `.tar` / `.tar.gz` / `.tgz` / `.tar.bz2` / `.tbz2`，自动处理中文文件名编码
- 输入新旧版本号，自动生成**左右分栏对比**的 HTML 报告
- 左侧文件树，按颜色标记：🟢 新增 / 🔵 修改 / 🟠 格式变化 / 🔴 删除 / 🟣 重命名
- 文件树支持「全部 / 新增 / 修改 / 格式变化 / 删除 / 重命名」过滤标签，可任意组合
- 支持目录折叠展开，一键全部展开/折叠
- 点击文件查看代码差异（新增/修改/删除行高亮，行号着色）
- **纯文本变更清单**，按新增/修改/格式变化/删除/重命名分类列出所有变更文件
- 差异展示方式可选：**全部内容** 或 **仅差异上下文**（前后各 3 行）
- 自动导出新版本和旧版本的变更文件，空文件正常导出；报告、oldVersion/newVersion 与 `上线操作说明.txt` 成组提交，读取、写入或最终替换失败时回滚到上一版完整产物；强退或断电留下的事务日志及批次根内部暂存物会在下次启动/生成时自动收敛，多项目重跑会整体替换 old/new 根以清除已移除项目
- 导出文件按 Git `.gitattributes` + `core.autocrlf/core.eol` 或 SVN `svn:eol-style` 匹配所选版本应有的换行符
- 支持 **glob 排除规则**（`*.class`、`target/**` 等），避免编译产物干扰
- 二进制/归档文件（`.jar`、`.war`、`.class` 等）标记变更但不展示内容
- Git/SVN 可执行文件路径自动探测（PATH → 注册表 → 常见安装目录），找不到时提示安装命令行工具
- 中文编码自动适配（子进程输出 + 文件内容均 UTF-8 → GBK 回退）
- 配置自动记忆，下次打开恢复上次设置

## 运行

### 开发环境

```bash
pip install jinja2
python main.py
```

### 打包为 exe

```bash
build.bat
```

打包后的 exe 在 `dist/CompareTool.exe`。使用 `--console` 模式打包，确保 git/svn 子进程有终端可用。应用图标使用 `assets/icons/app.ico`，打包时会同时写入 exe 图标和运行时窗口图标。

## 使用说明

1. 选择项目目录，选择版本控制类型（Git / SVN / 文件夹 / 压缩包 / Git多版本 / SVN多版本）
2. Git/SVN 模式点击「获取版本列表」查看可用版本（含提交注释，支持在当前列表内搜索；单击选中后点「←填入」或双击直接填入）
3. Git多版本/SVN多版本模式点击「获取版本列表」后可 `Ctrl/Shift` 多选版本，也可手工用逗号、分号或换行输入多个版本号；搜索过滤和隐藏列表不会清空已选版本
4. 确认项目名，工具会从有效项目目录/新版本文件夹/新版本压缩包自动推断；Git/SVN/Git多版本/SVN多版本可从项目名下拉中选择最近项目并同步回填项目目录；推断不到时需手动填写
5. 输入/修改排除规则（支持 `*` 和 `**` 通配符）
6. 设置输出目录，可选填写输出批次名称，点击「生成比对报告」
7. 生成完毕后自动询问是否打开报告

**版本列表操作**：Git/SVN/Git多版本/SVN多版本获取版本列表后，搜索框只过滤当前已经展示的最近版本，不会额外查询仓库。点击「隐藏版本列表」会收起列表区域，便于查看下方多项目任务；按钮会切换为「显示版本列表」，再次点击可恢复列表。隐藏列表不会清空版本缓存、搜索条件或多版本选择状态；重新获取版本列表时会自动展开。

**多项目总报告**：配置好当前项目后，填写/确认「项目名」，点击「添加到多项目任务」。任务列表支持编辑、删除、清空和持久化保存。任务会保存排除规则、是否使用项目名、差异展示方式等设置快照。点击「生成多项目总报告」后，工具会按任务顺序处理所有项目，并在批次根下创建独立的 `multi_run_yyyyMMdd_HHmmss_SSS_<8位随机十六进制>/` 运行目录。该次报告、上线说明和源码包都保存在此目录：

```
multi_run_.../multi_compare_report_yyyyMMdd_HHmmss_SSS.html
multi_run_.../上线操作说明.txt
multi_run_.../oldVersion/项目名/...
multi_run_.../newVersion/项目名/...
```

多项目任务允许混用 Git、SVN、文件夹、压缩包、Git多版本和 SVN多版本。任一任务失败时，本次总报告生成失败，不跳过项目。总报告的变更清单按新增/修改/格式变化/删除/重命名汇总，不按项目分组；每条路径是否带项目名由所属任务自己的「报告树及变更清单使用项目名」决定。若多个项目最终展示路径完全相同，工具会停止生成并提示用户开启相关任务的项目名展示，避免文件树和清单出现歧义。

**输出批次名称**：在「输出目录」下额外增加一层子目录，便于按系统版本或上线批次归档。每次启动默认当天日期（如 `20260530`），不写入配置文件，用户可手工修改或清空。例如输出目录为 `C:/Users/12939/Desktop/444`，输出批次名称为 `订单系统_v1.0.1`，则单项目产物直接生成到 `C:/Users/12939/Desktop/444/订单系统_v1.0.1/`；多项目产物再进入该批次根下独立的 `multi_run_.../`。留空时以选择的输出目录作为批次根。生成前会提示本次真正写入的批次根或 multi run 目录，需确认后继续。

**文件夹对比模式**：选择两个文件夹分别作为旧版本和新版本。生成开始时先同时捕获两端文件身份并快照到 CompareTool 专用临时目录，再用分块字节读取判断差异；无需 VCS，也不会在比对途中混入源目录的后续变化。

**压缩包比对模式**：选择两个压缩包作为旧版本和新版本，工具自动解压到专用临时目录后比对。支持 `.zip`、`.jar`、`.war`、`.ear`、`.aar`、`.tar`、`.tar.gz`、`.tgz`、`.tar.bz2`、`.tbz2` 格式。解压会拒绝 `../`、绝对/盘符路径、Windows 非法路径及 ADS、符号链接、硬链接和特殊文件。同时限制最多 100,000 个成员、单成员 2 GiB、累计展开 10 GiB 和 1000:1 压缩比，超限则在写入前中止。

**Git多版本 / SVN多版本模式**：用于从多个需求相关提交或修订中生成文件级首尾净差异。选中版本决定候选文件集合；每个文件分别取“首次选中变更之前”的真实状态作为 old，取“末次选中变更之后”的真实状态作为 new。工具不读取更晚的工作副本/HEAD，不为所有文件套用统一最高版本，也不通过 cherry-pick 或 SVN merge 合成文件。

例如选中 `r3`（修改 `B.java`）和 `r6`（修改 `A.java`）：

```text
B.java：old = B@r2，new = B@r3
A.java：old = A 在 r6 前的真实状态，new = A@r6
```

同一文件跨多个选中版本时，比较首次选中前与末次选中后的最终净结果；中间未选中的修改不单独展示，但会自然体现在末次选中版本的真实文件状态中。新增后又删除、修改后又恢复等最终完全抵消的文件不进入报告和导出。完整语义与场景见 [`docs/multi-version-file-endpoints.md`](docs/multi-version-file-endpoints.md)。

Git多版本只接受当前分支第一父历史中的提交，合并提交相对第一父提交计算净变化；浅克隆缺少父对象时中止。Git 会同时用可靠阈值和低阈值检查重命名；同提交按 `D/R → A/R/M` 完整竞争矩阵、跨提交按待定删除源到后续 `A/R/M` 目标，用 Git 原生 blob 相似度复核。只要身份跨越选中端点却无法唯一确认，就中止整个任务，不生成猜测包；无关中间文件的低相似重命名或类型变化不会阻断。SVN多版本沿当前项目 URL 的 revision 历史追踪文件及目录移动，通过 `copyfrom-path`、历史项目前缀和删除覆盖关系保留文件身份；项目根/祖先/嵌套目录移动、子文件移出目录或覆盖目标、移动后删除源祖先均按真实文件身份处理，普通 copy 和同源多目标不会被强猜成唯一 rename。

归档解压和多版本模式共用 CompareTool 专用临时目录，成功或失败后都会自动清理，不会修改真实项目目录。可通过环境变量 `COMPARETOOL_TEMP_DIR` 显式指定位置；未指定时，源码/exe 位于非系统盘则优先使用其同盘 `.tmp/comparetool_runtime`，Windows 下源码/exe 位于 C 盘且 D 盘可用时优先使用 `D:\applications\_cache\CompareTool\tmp`，只有前述位置都不可用时才回退到系统临时目录。Git多版本列出当前分支第一父历史最近 100 条提交，并用 `[merge]` 标记合并提交；SVN多版本只列出当前项目 URL 相关的最近 100 条 revision，不查询全仓库提交。

大文件导出、多版本端点快照和 Git 重命名候选评分均采用流式处理，不把完整二进制载入内存；Git/SVN 的可变版本、检出配置与仓库身份会在任务开始时固定。Git/SVN 多版本的原始命令输出、历史记录数、路径字节、逻辑文件数、端点文件数、源字节和最坏落盘量都有硬上限，并在写入前检查同卷剩余空间。报告生成有跨项目共享的明细数、实际 JSON 转义后 manifest 字节、文本、行对字符组合复杂度和最终 UTF-8 HTML 预算；最终单文件报告硬限 80 MiB，超限时原子失败且不会覆盖旧报告。详情超限时只省略展开内容，弹窗仍使用独立的轻量路径清单并明确标出“已列出/总数”，源码包和上线说明仍覆盖全部变更。文件夹和压缩包会先同时捕获新旧两端身份，以 Windows 卷序列号/FileId（其它平台使用设备号/inode）绑定预捕获路径和复制句柄，并限制快照文件数、逻辑字节数及所需磁盘空间。每次多项目输出目录使用“毫秒时间戳 + 随机标识”，并发生成不会互相覆盖。

**上线操作说明**：每次生成都会在报告、`oldVersion`、`newVersion` 同级生成带 UTF-8 BOM 的说明文件；单项目名为 `<项目名>_上线操作说明.txt`，多项目名为 `上线操作说明.txt`。文件列出需要从目标环境删除的旧路径和重命名对应关系；多项目路径始终带项目名，不受报告展示选项影响。即使本次没有删除或重命名也会生成并明确写“无”，防止交付方误判漏文件。四类输出作为同一事务提交和恢复：生成前从用户配置的可信输出根向下检查所有祖先并记录正式目标状态，所有源码/报告/说明 stage 直接创建在该可信根，提交锁内复核，较早启动的慢任务不能覆盖期间产生的新结果，生成期间插入 batch junction 也不能把暂存内容导向根外；固定锁文件拒绝链接、联接点和硬链接。事务日志同时绑定 stage/target/backup 的流式内容摘要与文件系统身份；恢复删除前先把对象原子移入由签名事务信息确定性派生的隔离名，恢复状态机可在隔离后崩溃或删除失败时幂等续做，若发现用户替换或修改对象则保留现场而不按旧路径静默删除。签名 journal 本身承担中断恢复授权，不依赖提交后可能已清理的 stage 所有权标记。

**重命名处理**：普通 Git/SVN、文件夹和压缩包模式保持原有重命名识别；Git多版本/SVN多版本由历史端点规划器追踪文件身份，不再对最终删除/新增按内容二次猜测。重命名同时发生编码/BOM/换行变化时会明确显示格式说明；跨越排除边界时改为新增或删除。导出时 oldVersion 使用旧路径，newVersion 使用新路径，并把旧路径写入 `上线操作说明.txt`。普通 Git 比对遇到文件类型变化会中止；Git 多版本历史中的类型变化只延续同路径身份，最终选中端点为非普通 mode、`svn:special` 或其它非普通文件时仍会中止。格式净差异另用仓库原始字节判断，防止换行转换把真实格式变化过滤掉。

## 排除规则

工具内置一套通用默认排除规则，每行一个 glob 模式。新项目没有专属配置时使用这套默认模板；在界面里修改后，会按项目目录（压缩包按新版本压缩包完整路径）单独记忆。

```
*.class
**/target/**
**/.git/**
**/.idea/**
**/node_modules/**
**/__pycache__/**
...
```

规则语法：
- `*.class` — 匹配任意深度的 .class 文件
- `target/**` — 匹配 target 目录下所有文件
- `**/test/**` — 匹配任意位置的 test 目录

## 配置文件

`compareTool_config.json` 自动保存上次的项目路径、VCS 类型、输出路径、多项目任务列表、最近项目列表，以及按项目路径记忆的排除规则和显示选项。写入失败会明确报错，不再显示假成功；启动时会忽略 schema 损坏或 VCS 类型未知的多项目任务，避免整个窗口无法打开。最近项目按 Git/SVN 家族分组，每组最多保留最近 10 个有效项目。输出批次名称不持久化，每次启动默认当天日期。新项目没有专属规则时，直接使用代码内置默认模板；旧版全局 `exclude_rules` 不再作为默认模板来源。
